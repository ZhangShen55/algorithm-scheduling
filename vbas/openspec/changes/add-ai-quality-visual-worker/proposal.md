## Why

当前项目已经具备单帧图片视觉推理能力，但还缺少按课次视频进行批处理分析、结果落库、抓拍存储和指标闭环的 Worker 能力，无法满足《视觉分析服务概要设计.pdf》中以 Kafka 任务驱动课堂质量分析的目标。

本次变更先建设第一版可落地链路：以 Kafka 消息为准处理一节课的视频，复用现有视觉模型生成课堂质量相关指标，并将过程状态、分钟级时间线、抓拍事件和指标结果写入 `ai_quality` 数据库。

## What Changes

- 新增独立 AI 课堂视觉分析 Worker 入口，与现有 FastAPI HTTP 推理服务分离。
- 新增 Kafka 消费能力，按 Kafka 消息触发课次视频分析，不依赖、不写入 `lesson_video`。
- 新增视频 URL 下载、实际时长识别、按 30 秒间隔抽帧能力。
- 复用现有人数、人脸、学生行为、教师行为、教师头部姿态模型，形成第一版分析结果。
- 新增抓拍图片存储能力，将抓拍图缩放到原图 1/4 后写入配置目录；NFS 不可写时本地使用项目内 `blobstor/image` 替代，数据库 `image_url` 仅保存 `cv/{task_id}/{image_id}.png` 相对路径。
- 新增数据库写入闭环，覆盖 `lesson_ai_workflow`、`lesson_ai_job`、`lesson_behavior_timeline`、`lesson_snapshot_event`、`indicator_score_result`。
- 新增学生异常行为聚合统计写入，覆盖 `lesson_student_behavior_stat`，第一版仅写入玩手机和趴桌睡觉。
- 调整 `lesson_snapshot_event` 口径：该表仅保存核心课堂快照事件，不保存所有 30 秒抽帧图片；快照触发阈值和保存上限均通过 `config.toml` 配置。
- 新增学生核心快照事件：
  - `behavior_type=2 学生抬头高峰`：按抬头率取最高 N 张，再按最低抬头率阈值过滤。
  - `behavior_type=3 学生阅读专注`：按 `Read_W / present_count` 取最高 N 张，再按最低阅读占比阈值过滤。
  - `behavior_type=4 学生睡觉`：睡觉人数或睡觉占比达到配置阈值时保存。
  - `behavior_type=5 学生玩手机`：玩手机人数或玩手机占比达到配置阈值时保存。
- 新增教师核心快照事件：`behavior_type=1 教态预警`，连续配置帧数非面向学生或低头时保存。
- 新增第一版正式指标：
  - `E2-01 到课率`：检测人数中位数 / 应到人数。
  - `E3-01 前排就座率`：基于检测人数的 20%～30% 稳定随机占位人数 / 应到人数。
  - `E4-01 后排就座率`：基于检测人数的 20%～30% 稳定随机占位人数 / 应到人数。
  - `E5-01 平均抬头率`：人脸数 / 人数。
  - `A6-01 面向学生占比`：教师头部姿态正面占比，作为固定机位下的近似口径。
- 新增失败处理：视频不可用等任务级失败重试 3 次，最终失败后落库失败状态并提交 Kafka offset。
- 新增幂等重跑策略：同一 `task_id` 重跑时清理旧时间线、抓拍、统计结果，再重写本次结果；指标结果使用 UPSERT。
- 新增学生异常行为统计策略：固定跳过课程前 3 分钟，从第 3 分钟处往后统计；同一 `task_id + behavior_type` 只写一行；`detect_count` 累计有效统计窗口内的人次；`peak_period_desc` 从异常候选段按严重程度排序后最多保留 5 段，并按时间顺序展示。
- 第一阶段不实现面向课件/板书/电脑、讲台驻留/巡视、真实前后排识别、教室上座率和完整 DLQ 管理。

## Capabilities

### New Capabilities

- `ai-quality-visual-worker`：定义 Kafka 驱动的课次视频视觉分析 Worker 行为，包括任务消费、视频抽帧、模型分析、NFS 抓拍、数据库写入、指标聚合、失败处理和幂等重跑。

### Modified Capabilities

- 无。

## Impact

- 影响代码：新增 Worker 相关模块、配置、启动入口、数据库访问封装、Kafka 消费封装、视频处理封装、NFS 存储封装、指标聚合与评分逻辑。
- 影响运行环境：需要 Kafka broker、MySQL `ai_quality` 数据库、可访问的视频完整 URL、抓拍写入目录、现有模型文件和推理依赖；本地默认使用项目内 `blobstor/image`。
- 影响数据：新增或更新课次分析工作流状态、任务状态、分钟级行为时间线、抓拍事件、学生异常行为聚合统计、指标结果。
- 兼容性：不改变现有 HTTP 图片推理接口行为；第一版 Worker 并发默认按单课次处理，并发数配置化，为后续多实例部署预留空间。
