# 部署说明

## 统一运行约定

三类环境使用相同的 FastAPI 路由、服务层、结果转换和项目本地模型。普通 OCR 使用 PP-OCRv6 medium；公式能力使用 PP-DocLayout_plus-L 和 PP-FormulaNet_plus-M。正式配置只保存在宿主机，通过以下方式只读挂载：

```bash
-v "$(pwd)/config.toml:/app/config.toml:ro"
```

设备格式只有三种，每份配置只启用其中一个值：

```toml
# 三选一；切换设备时注释当前值并启用目标值
device = "cpu"
# device = "cuda:0"
# device = "npu:0"
```

设备编号必须是非负整数。配置的加速设备不存在、驱动不可用或插件未加载时，服务直接启动失败，不会自动回退到 CPU。

公式服务配置示例：

```toml
[formula]
enabled = false
layout_model_dir = "models/PP-DocLayout_plus-L"
recognition_model_dir = "models/PP-FormulaNet_plus-M"
recognition_batch_size = 1
layout_threshold = 0.5
```

`enabled = true` 时，服务启动阶段初始化公式版面定位和识别模型；请求字段 `enable_formula` 还须设为 `true` 才会执行公式推理。两个公式模型解压后的运行文件合计约 716 MiB，部署时必须预留相应的镜像和磁盘空间，并在目标机单独验收模型加载内存。

每个容器默认只启动一个 Uvicorn worker，模型在应用 lifespan 中初始化一次并由请求复用。多实例或多卡部署应为每个容器准备独立配置。

## CPU

MacBook 开发环境使用 conda 和 `requirements.cpu.txt`，当前已在 Python 3.11、PaddleOCR 3.7.0、PaddlePaddle 3.3.1 上通过真实 medium 模型推理。

Mac CPU 上的真实公式集成测试也已通过。一次约 86 秒的记录包含首次加载普通 OCR、版面定位、公式识别共四个模型以及单次推理，只反映该次集成测试开销，不是性能指标；延迟、吞吐和资源容量必须在目标部署机重新测量。

Docker 中的 CPU 模式复用 CPU/GPU 镜像，将 `device` 配置为 `cpu`。该镜像包含 NVIDIA 运行时，体积较大；这是共用一个 Dockerfile 的取舍。

Paddle 3.3.0 GPU 包在 CPU 模式启用 MKL-DNN 时，PP-OCRv6 PIR 模型存在 OneDNN 属性转换兼容问题，因此跨环境示例默认使用 `enable_mkldnn = false`。只有在目标 Paddle 版本完成真实推理验证后再显式开启。

## NVIDIA GPU

CPU/GPU 镜像使用 Paddle 官方运行时：

```text
ccr-2vdh3abv-pub.cnc.bj.baidubce.com/paddlepaddle/paddle:3.3.0-gpu-cuda11.8-cudnn8.9
```

该地址来自 Paddle 官方中文安装文档，在国内网络下比 Docker Hub 更稳定。

运行条件：

- x86_64 Linux 主机。
- 与 CUDA 11.8 运行时兼容的 NVIDIA 驱动。
- NVIDIA Container Toolkit。
- 容器内可见的目标 GPU。

配置中的编号是容器逻辑编号。`--gpus all` 暴露全部显卡时，`cuda:2` 表示容器内第三张卡。只向容器暴露物理卡 2 时，它通常映射为容器逻辑 `cuda:0`，配置应按容器内编号填写。`cuda:<编号>` 是应用配置格式，调用 PaddleOCR 和公式流水线时会转换为 Paddle 使用的 `gpu:<编号>`。

当前 MacBook 没有 NVIDIA 设备，GPU 模型加载和真实请求尚未完成真机验收，公式版面定位与识别也未在 NVIDIA GPU 上验证，不能据此声明 GPU 生产可用。

## Ascend NPU

NPU 与 CPU/GPU 分开构建，使用 `docker/Dockerfile.npu`。当前缺少以下目标环境信息：

- Ascend 型号，例如 310P 或 910B。
- 主机驱动和 CANN 版本。
- 对应 CANN 基础镜像。
- PaddlePaddle、PaddleOCR、PaddleCustomDevice 兼容版本。
- 容器设备映射和运行参数。

因此 `requirements.npu.txt` 尚未锁定 PaddleCustomDevice，`NPU_BASE_IMAGE` 没有默认值，NPU 镜像不能作为正式交付物构建。确定兼容矩阵后，应先补齐依赖和基础镜像，再在目标 Ascend 主机运行模型校验、接口契约和真实图片推理测试。

NPU 真机测试完成前，`npu:<编号>` 只代表应用代码和配置入口已预留；普通 OCR 与公式识别均不能据此视为生产可用。
