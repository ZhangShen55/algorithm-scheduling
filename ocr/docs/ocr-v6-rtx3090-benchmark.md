# OCR v6 RTX 3090 压测报告

## 1. 结论

- 最终镜像：`ocr:v6_amd`
- 推荐 OCR `recognition_batch_size`：`4`
- 推荐客户端并发：`2`
- 服务端 `max_concurrency`：保持 `1`，并发请求排队进入单引擎
- 推荐组合复验：100/100 成功，0 个 HTTP 5xx，`13.468 QPS`，P95 `152.716 ms`
- 公式识别：真实图片识别出 28 个公式，单请求约 `9.806 s`

## 3. 配置和输入

主压测配置：

```toml
[ocr]
device = "cuda:0"
recognition_batch_size = 1 # 按 1、4、8、16 分组替换
enable_hpi = false
max_concurrency = 1

[formula]
enabled = false
recognition_batch_size = 1
```

固定输入：

| 文件 | SHA-256 | 用途 |
| --- | --- | --- |
| `ocr-test.jpg` | `1b3978f3708bc31e3acfe603b052531a480db87ebaa1460559ee7d3eb1160593` | OCR 主矩阵 |
| `formula-document.png` | `3dc2f9bdafa23e1b88910d323d46815d7c60dab19800784bfbdbea58412db2e5` | 公式功能验证 |

每个组合先执行 10 个不计量预热请求，再执行 100 个计量请求。压测从服务器本机访问
`http://127.0.0.1:8866/ocr/prediction`。部署前 RTX 3090 为空闲状态，显存占用 3 MiB；
OCR 模型加载后的矩阵基线为 1043 MiB，其中 Python 进程约 1034 MiB。

## 4. 正确性判定

内容摘要使用文字、文字框、公式内容和公式区域计算，不包含模型置信度；原始响应摘要保留
完整置信度。20 组内容摘要均为 `8c763fa078097ca0`，每组 100 个响应一致。

batch 1 的原始摘要为 `40c5327d81bb041a`，batch 4/8/16 为
`ee472247b3db1fd8`。逐项比较确认文字和文字框完全一致，仅一项置信度从
`0.9399439692` 变为 `0.9475528002`，最大差值约 `0.007609`。该差异保留在报告中，
不作为识别内容错误。

有效组合要求：100% 成功、0 个 HTTP 5xx、内容摘要与基线一致、无客户端错误、无服务端
ERROR/Traceback/CUDA/OOM 日志。20 组均满足要求。

## 6. 推荐参数计算

全部有效组合的最高 QPS 为 `14.173`，95% 阈值为 `13.464`。各 batch 峰值：

| Batch | 峰值 QPS | 是否达到全局峰值 95% |
| ---: | ---: | --- |
| 1 | 13.007 | 否 |
| 4 | 14.173 | 是 |
| 8 | 13.908 | 是 |
| 16 | 14.107 | 是 |

选择达到阈值的最小 batch，因此推荐 batch 4。batch 4 自身峰值的 95% 为
`13.464 QPS`，最小合格客户端并发为 2。并发继续增大几乎不增加吞吐，但 P95 从
`147.522 ms` 上升到 291 ms、584 ms 和 1176 ms，因此不推荐并发 4/8/16。

推荐组合重新启动后独立复验：100/100 成功，`13.468 QPS`，平均 `147.660 ms`，
P95 `152.716 ms`，0 个 HTTP 5xx，内容摘要保持一致。

## 7. 公式、重启和失败路径

开启服务端公式配置后，`formula-document.png` 返回 1 个图片结果、28 个公式；单请求
约 `9.806 s`，压测脚本记录为 `9.811 s`，运行时 GPU 显存约 2191 MiB。公式路径不参与
OCR batch 参数搜索。

容器重启前后，同一 OCR 图片的响应摘要均为 `40c5327d81bb041a`，版本接口和 OCR 接口
均成功。主动重启产生的 SIGTERM 日志属于正常终止，重启后重新出现
`Application startup complete.`。

独立临时容器已复现并记录以下失败日志，正式验收容器在验证后保持可用：

- `配置文件不存在：/app/config.toml`
- `GPU 设备 cuda:1 不可用`
- `检测模型目录不存在：/app/models/not-found-det`
- `Bind for 0.0.0.0:8866 failed: port is already allocated.`

服务器证据保存在 `/root/ocr-v6-amd-delivery/results/`；其中 `matrix/` 是最终双摘要矩阵，
`matrix-raw-v1/` 保留第一轮原始摘要结果。

## 8. 适用边界

本结论基于单张固定测试图片、单 OCR 引擎、单 RTX 3090 和本机 HTTP 请求。它适合当前
图片尺寸与文字分布，不代表所有扫描件、PPT 页面或超大图片。批量业务上线后应按真实图片
集合复测，并持续观察 P95、显存、错误率和识别内容；不得把客户端并发解释为 GPU 多引擎并行。
