# 接口兼容说明

## OCR 识别

接口：

```text
POST /ocr/prediction
Content-Type: application/json
```

请求中的 `key` 和 `value` 是按下标对应的平行数组：

```json
{
  "key": ["图片ID-001", "图片ID-002"],
  "value": [
    "<纯 Base64>",
    "data:image/png;base64,<Base64>"
  ]
}
```

- `key[i]` 是字符串类型的图片 ID，不要求等于 `image`。
- `value[i]` 是对应图片的数据，可以是纯 Base64，也可以保留 `data:image/<格式>;base64,` MIME 前缀。
- `key` 和 `value` 必须非空且长度相同。
- 服务先解码全部图片，再开始本批次推理。任一图片无效时整批失败，不执行部分图片。

可选字段 `enable_formula` 默认为 `false`：

```json
{
  "key": ["图片ID-001"],
  "value": ["<纯 Base64>"],
  "enable_formula": true
}
```

公式识别受请求和服务端配置两级开关控制：

| 请求 `enable_formula` | 服务端 `[formula].enabled` | `formula_results` |
| --- | --- | --- |
| `false` 或未传 | 任意值 | `[]`，不执行公式推理 |
| `true` | `false` | 按图片返回 `disabled`，普通 OCR 正常返回 |
| `true` | `true` | 使用项目本地 `PP-DocLayout_plus-L` 定位、`PP-FormulaNet_plus-M` 识别，按图片返回 `success` 或 `error` |

请求开启而服务端关闭时，响应示例为：

```json
{
  "err_no": 0,
  "err_msg": "",
  "key": ["图片ID-001"],
  "value": ["[]"],
  "formula_results": [
    {
      "image_id": "图片ID-001",
      "status": "disabled",
      "message": "服务端未启用公式识别功能",
      "formulas": []
    }
  ]
}
```

两级开关均开启时，响应按请求顺序为每张图片返回一组公式结果：

```json
{
  "err_no": 0,
  "err_msg": "",
  "key": ["图片ID-001"],
  "value": ["[{\"text\":\"E=mc²\",\"confidence\":0.98,\"text_region\":[[10,20],[160,20],[160,60],[10,60]]}]"],
  "formula_results": [
    {
      "image_id": "图片ID-001",
      "status": "success",
      "message": "",
      "formulas": [
        {
          "latex": "E=mc^{2}",
          "formula_region": [[10, 20], [160, 20], [160, 60], [10, 60]],
          "detection_confidence": 0.96
        }
      ]
    }
  ]
}
```

公式字段约定：

- `latex`：公式识别结果。
- `formula_region`：公式区域的四个整数坐标点。
- `detection_confidence`：`PP-DocLayout_plus-L` 给出的版面检测置信度；接口不提供也不伪造公式识别置信度。
- 图片公式处理正常但未定位到公式时，仍返回 `status: "success"`，`formulas` 为 `[]`。

单张图片的公式推理异常只将该图片标记为 `error`，同批其他图片继续处理：

```json
{
  "image_id": "图片ID-002",
  "status": "error",
  "message": "公式识别失败",
  "formulas": []
}
```

该局部错误不改变普通 OCR 外层成功响应，`err_no` 仍为 `0`。公式结果是附加信息，不会删除、替换或改写普通 OCR `key`、`value` 中的结果；普通 OCR 识别出的疑似公式文本也原样保留。

成功响应：

```json
{
  "err_no": 0,
  "err_msg": "",
  "key": ["图片ID-001", "图片ID-002"],
  "value": [
    "[{\"text\":\"第一张结果\",\"confidence\":0.99,\"text_region\":[[0,0],[100,0],[100,30],[0,30]]}]",
    "[{\"text\":\"第二张结果\",\"confidence\":0.98,\"text_region\":[[0,0],[100,0],[100,30],[0,30]]}]"
  ],
  "formula_results": []
}
```

兼容约束：

- 响应 `key` 原样返回请求中的图片 ID，顺序不变。
- `value` 与 `key` 数量相同，`value[i]` 是 `key[i]` 对应的 OCR 结果。
- 每个 `value[i]` 都是 JSON 字符串，不是原生数组；解析该字符串后得到当前图片的结果数组。
- `text` 为字符串，`confidence` 为浮点数，`text_region` 为四个整数坐标点。
- 普通 OCR 推理阶段任一图片失败时，整个请求返回错误，不返回半批普通 OCR 结果；公式推理异常按前述规则隔离到单张图片。

某张图片没有识别结果时仍是成功响应：

```json
{
  "err_no": 0,
  "err_msg": "",
  "key": ["图片ID-001"],
  "value": ["[]"],
  "formula_results": []
}
```

请求参数或普通 OCR 推理错误使用兼容错误结构，HTTP 状态保持 200，`err_no` 为非零值。错误响应不会返回部分图片结果：

```json
{
  "err_no": 4002,
  "err_msg": "图片 Base64 数据无效",
  "key": ["results"],
  "value": ["[]"],
  "formula_results": []
}
```

当前错误分类：

- `4000`：请求模型校验失败。
- `4001`：`key`、`value` 为空或数量不一致，或者图片 ID 为空。
- `4002`：Base64、图片 MIME 前缀、图片格式或图片大小无效。
- `5001`：OCR 推理失败。

客户端响应不会包含底层异常堆栈和模型路径，完整异常只写入服务端日志。

## 版本信息

接口：

```text
GET /ocr/getVersion
```

响应保留以下字段：

- `status`
- `AppVersion`
- `AppStartTime`
- `NowTime`
- `RunTime`
- `Memory usage`
- `GPU usage`
- `Total_RegProcess_Tasks`
- `Total_DetectProcess_Tasks`

CPU 或 NPU 模式下，`GPU usage` 仍会返回，并明确表示当前未使用 NVIDIA GPU。两个任务计数按成功处理的图片数量增加；一次成功处理两张图片时各增加 `2`。
