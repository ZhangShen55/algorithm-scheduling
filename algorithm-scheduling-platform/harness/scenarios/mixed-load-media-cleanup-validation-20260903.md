## 新发现与后续优先级

1. **P0，Vision 租约连接瞬时故障恢复**：Control 短暂不可达不应直接让长时间视觉节点失败；
   需要有限重试、总时限、中文非空原因和 Control 重启故障注入回归。
2. **P0，在线 200 并发业务失败**：116 次失败使本轮在线门禁未通过；先补全租约申请、续租、
   下游连接和响应解析的异常分类日志，再依据事实修复，不能只放大超时掩盖问题。
3. **P1，在线错误语义**：当前所有租约错误均返回“等待容量超时”，会误导 A 服务和运维；
   应区分真正容量等待超时与平台依赖故障，同时保持既有 HTTP/业务响应契约的兼容边界。
4. **P1，压测活动互斥**：业务压测期间发生服务发布使本轮不具备稳定版本验收条件；后续正式验收
   应锁定镜像 ID 和配置，在压测窗口禁止替换目标服务，异常情况下保留旧容器日志。
5. **P2，监控证据**：`/ops/operator-instances` 的 `inflight_by_pool` 是算子心跳上报值，2 秒采样
   未捕获在线瞬时在途；后续应直接采集 active lease 快照，并降低全目录 `du` 频率。

本轮不能作为里程碑 2B 的混合压力通过证据；它是有效的缺陷发现与媒体生命周期通过证据。
