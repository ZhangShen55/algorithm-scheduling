# 里程碑 2B 真实业务泳道与完整验收场景

## 目标

本场景承接三卡部署报告中的剩余缺口：修复 FaceRec 三实例 GPU 证据合同，贯通 PPT、ASR、
视觉和在线真实业务泳道，并执行全部 217 条反例和 26 条压力用例。

历史 release `v1.0_260812/7efac20cf980ee64ea78fe297af6dfdfb2df5b28` 是只读基线，
不得覆盖。后续每次执行必须使用当前完整 Git SHA 建立新的不可变 release 目录。

## 固定执行顺序

```text
1. FaceRec 三卡 GPU 证据关闭 + 部署层用例
2. PPT/ASR 离线泳道 + 所属反例/压力
3. 教师/学生视觉泳道 + 所属反例/压力
4. 在线图片/实时 ASR/人脸管理 + 所属反例/压力
5. 全部 217 反例 + 26 压力用例重新执行和总报告
```

前序失败不允许标记阶段完成。无依赖的实现可以继续，但最终验收不得存在“未执行及原因”。

## 泳道证据要求

| 泳道 | 必需真实边界 | 不接受的替代证据 |
| --- | --- | --- |
| PPT | A API、Outbox/Kafka、DAG、下载、租约、真实切片、manifest、OCR、关键词、查询 | 直接调用 PPT/OCR Smoke |
| ASR | A API、Outbox/Kafka、DAG、下载、WAV、真实 v1.1.8、脑图、查询 | 直接调用 ASR HTTP |
| 视觉 | course command、T/S 抽帧、VBas 租约、自适应细化、聚合、visual event、查询 | 单独 VBas 帧推理 |
| 在线 | 网关、请求级/会话级租约、真实图片算子或 WebSocket、释放与恢复 | 绕过网关直接调用算子 |

所有任务状态必须由运行中的平台服务推进。测试不得调用 Repository 完成节点或直接修改任务终态。

## 用例目录合同

217 条反例和 26 条压力用例都必须具备稳定 ID、阶段、前置条件、动作、预期、超时、清理和
证据路径。最终聚合器必须断言：

- 权威用例数量分别为 217 和 26；
- 每个 ID 唯一且恰好执行一次；
- 最终不存在“未执行及原因”；
- 任何失败都会使 `overall_status=失败`；
- 报告和原始证据属于同一 release tag、Git SHA 和容器 revision。

## 失败记录

失败保留原始状态和中文原因。修复后在新 Git SHA 对应的新目录执行，不回写旧报告。
与失败无依赖的任务可继续；数据安全、错误 GPU、磁盘耗尽或既有容器边界失败时停止相关操作。

## 完成结论

只有 FaceRec 三实例、四类真实泳道、217 条反例和 26 条压力用例全部通过，且 OpenSpec、
完整测试、Compose、镜像身份和 Harness 一致性门禁通过，场景结论才能写为“符合”。
