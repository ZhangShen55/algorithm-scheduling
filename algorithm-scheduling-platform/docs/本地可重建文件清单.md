# 本地可重建文件清单

本文只描述 `algorithm-scheduling-platform/` 的本地清理边界。是否可重建与是否应立即删除是两件事：正在使用的开发环境即使能重建，也应在替代环境验证完成后再删除。

## 可直接删除

以下内容由 Python、测试或质量工具自动生成，均已被 Git 忽略：

- `__pycache__/`、`*.pyc`：Python 字节码缓存。
- `.pytest_cache/`：Pytest 本地运行缓存。
- `.mypy_cache/`：Mypy 类型检查缓存。
- `.ruff_cache/`：Ruff 检查缓存。
- `*.egg-info/`：本地可编辑安装或构建生成的包元数据。
- `.DS_Store`：macOS Finder 元数据。
- `build/`、`dist/`：本地构建产物。正式发布的 wheel 应由构建流程重新生成并上传制品库，不以 Git 文件作为权威来源。

删除这些内容不会删除任务数据、迁移、源码或测试。下一次运行相应工具时会自动重新生成。

## 可重建但本轮保留

- `.venv/`：平台当前开发和验证使用的虚拟环境，约 188 MB。它可以根据 `pyproject.toml` 重建，但本轮保留，直到新的平台环境完成依赖安装和全量测试。

## 不得作为缓存删除

- `migrations/`：PostgreSQL DDL 和数据库演进记录。
- `deploy/`：Compose、部署说明和运维手册。
- `harness/`：架构决策、场景证据与验证命令。
- `tests/`：单元、契约和集成测试源码；只允许删除其中的 `__pycache__/`。
- `packages/`：平台公共包与算子注册客户端源码；只允许删除其中的缓存和构建元数据。
- `docs/`、`README.md`、`AGENTS.md`、`Makefile`、`pyproject.toml`：设计、操作约束与构建入口。

## 审计结论

本轮发现的过渡内容全部属于上面的可重建项，没有发现应删除的已跟踪过渡源码。清理前后均应运行 `git status --short --ignored algorithm-scheduling-platform`，确认没有出现已跟踪文件删除。
