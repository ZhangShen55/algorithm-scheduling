## Context

v1.0.2 和 v1.0.3 每次接收约 0.48 秒 PCM，并将块送入在线 ASR 和 FSMN-VAD。当前实现使用 `vad_cache` 轮换来限制历史增长，但 VAD 的连续状态也随之丢失；同时，VAD 返回的 `start_ms/end_ms` 没有用于样本级切分，当前语句直接收取整块 PCM。结果是自然停顿可能无法及时结束，最终退化为约 20 秒强制切段，或者把断点后的静音和下一句话开头归入错误语句。

`finished=true` 是字幕消费者的段落结束信号，不是纠正模型完成的批处理信号。每个已经确认结束的话段必须立即发送一个最终结果，下一段使用新的 `key`；不得等待三个 finished 段后再发送。

## Goals / Non-Goals

**Goals:**

- 让 v1.0.2/v1.0.3 使用连续 VAD 状态检测跨块语音起止点。
- 使用 VAD 断点把 PCM 按样本切分，并保存未归属音频到 pending PCM。
- 下一句开始时保留约 100 至 200 ms pre-roll，降低首字丢失风险。
- 每个自然结束事件立即进行对应纠正并发送 `finished=true`。
- 保留约 20 秒单段最大保护，限制异常场景下纠正输入和内存增长。
- 在没有自然结束事件时提供有界的空闲、最大段长和断开释放路径。
- 保持 v1.0.2/v1.0.3 WebSocket 请求、响应字段、`key`、`bg`、`ed` 和 `finished` 语义兼容。

**Non-Goals:**

- 不修改 v1.0.1 的实现、断句策略或输出格式。
- 不修改 `online_gateway_service` 或上游 0.48 秒 PCM 请求方式。
- 不累计三个 finished 结果后再输出，也不把三个完整 finished 音频段重复送入纠正模型。
- 不在本 change 中更换 ASR、VAD、Paraformer、SenseVoice 或标点模型。
- 不把 `bg/ed` 字段改为新的时间单位或新增响应字段。

## Decisions

### 1. 连续保留 VAD 状态，取消固定六块轮换

同一 WebSocket 会话内保持一个 VAD cache，跨越多个 0.48 秒块调用 `generate`。FunASR 的多语句检测模式在输出完整结束事件后会推进和清理内部检测状态；项目层只在自然结束已消费、空闲超时、约 20 秒强制切段或异常断开时释放 cache。这样 `max_end_silence_time` 的累计静音判断不会在 2.88 秒窗口边界被打断。

选择连续 cache 而不是继续每六块重建，是因为固定轮换会让 1000/1200 ms 端点参数失去连续时间基准。约 20 秒的项目层最大段长和 VAD 自身的多语句 reset 负责控制增长；不直接修改 FunASR 私有 `stats` 数组。

### 2. 维护绝对音频时间和 VAD 时间换算

项目层维护会话音频的绝对样本偏移、当前语句起点、已消费位置和 pending PCM。每个 VAD 事件先通过 cache 起始偏移或 FunASR 已消费帧偏移转换为会话绝对样本位置，再限制在已收到音频范围内。`start_ms/end_ms` 只用于切分，不直接当作当前 0.48 秒块的局部下标。

如果 FunASR 在多语句模式下返回 `[start_ms, -1]` 和 `[-1, end_ms]` 两个事件，事件处理器必须分别更新待开始语句和待结束语句，不能因为发现 end 事件就丢弃同一批结果中的后续 start 事件。

### 3. 使用 pending PCM 和 pre-roll 组装语句

所有收到的 PCM 先进入有界的未消费音频队列。确认语音结束时，按绝对 `end_sample` 将当前语句切到该位置；结束点之后已经收到的 PCM 不删除，而是进入 pending PCM。收到下一句 start 后，从 pending PCM 中定位起点，并向前扩展不超过 100 至 200 ms 的 pre-roll，随后建立下一句的纠正输入。

pre-roll 只用于音频识别上下文，时间字段仍以 VAD 的真实语音起点为准，避免为了补首字而扩大 `bg`。pending PCM 设定最大时长上限；超过上限的纯静音可以丢弃，但不能丢弃已确认属于下一句起点前的 pre-roll。

### 4. finished 事件立即发送

自然 VAD end 或约 20 秒保护触发后，服务立即对当前语句做一次最终识别和必要的标点处理，然后使用当前 `key` 发送一条 `finished=true`。发送完成后释放已经消费的语句 PCM；pending PCM 继续留在会话中，等待下一个 start。不得使用“等待三个 finished”作为输出条件。

### 5. 端点参数与最大段长分开管理

`max_end_silence_time` 作为 VAD 的静音确认参数，默认候选值为 1000 ms，并保留配置和测试能力以便与 1200 ms 对比。它只影响自然结束判定，不负责限制 PCM 内存。单段最大保护按上游块取整到 42 块，即约 20.16 秒；达到保护时也必须立即发送 finished，但要标记为保护切段的内部原因，不改变外部响应格式。

### 6. 断开安全与模型调用边界

发送前检查连接状态；若客户端已关闭，立即停止当前会话并释放所有缓存，不再调用 `send_json`。后续实现应将阻塞模型推理移出 WebSocket 事件循环或至少在推理前后处理断开状态，避免客户端保活超时后服务端继续发送。

## Risks / Trade-offs

- [风险] 连续 VAD cache 在异常无结束音频下仍会增长。→ 以 42 块约 20.16 秒强制完成语句，并设置 pending PCM 和静音上限。
- [风险] 端点返回时间与当前已接收块边界不一致。→ 使用样本级绝对偏移、范围裁剪和 pre-roll，并用合成断点测试验证不重叠、不丢失。
- [风险] pre-roll 可能造成相邻语句音频轻微重叠。→ pre-roll 只作为识别上下文，最终文本合并测试必须检查重复字，必要时使用文本重叠合并。
- [风险] 纠正模型推理时间超过一个上游块。→ 保持协议顺序和单会话串行处理；增加响应延迟和断开测试，后续再单独优化推理调度。
- [风险] 1000 ms 比 1200 ms 更容易在自然短暂停顿处切段。→ 在同一测试音频上记录句段数量、段长、finished 延迟和纠正变化，保留可回退配置。

## Migration Plan

1. 先在 OpenSpec 实现阶段只修改 v1.0.2/v1.0.3 共用会话逻辑和针对性测试。
2. 本地 `asr` 环境验证协议测试、合成断点切分、教师音频短片段和健康接口。
3. 将相同代码同步到 `192.168.29.12:/root/workspace/asr_online`，保留 GPU 配置并短时验证。
4. 若自然断句或字幕边界回归，回滚 v1.0.2/v1.0.3 代码到本 change 前版本；v1.0.1 始终不参与迁移。

## 全量验收测试设计

### 测试拓扑

- Mac 本地运行测试客户端，作为唯一音频发送方。
- `192.168.29.12` 的 `/root/workspace/asr_online` 启动一个 GPU `asr_online` 服务进程，Mac 客户端按 A→B→C 顺序建立 WebSocket 连接，前一路完成尾部 drain 后再启动下一路。
- A 固定对应 `/v1.0.1/seacraft_asr_online`，B 固定对应 `/v1.0.2/seacraft_asr_online`，C 固定对应 `/v1.0.3/seacraft_asr_online`。
- 三路都读取完整 `test/教师1_16k.wav`，不能只发送前 N 秒；发送前校验 16 kHz、单声道、16-bit，并记录完整音频时长和总块数。
- 三路连接使用独立输出文件、独立 watchdog 和独立资源采样；任意一路失败都保留现场，然后继续后续路由，不用短测代替全量结果。

### 原始结果和命名

每条原始响应仍按服务端返回的 JSON 原样写入 JSONL，不增加字段、不修改字段值：

- A：`test/A_v1_0_1_teacher1_full.jsonl`
- B：`test/B_v1_0_2_teacher1_full.jsonl`
- C：`test/C_v1_0_3_teacher1_full.jsonl`

每路另存一个 summary，记录路由、音频总时长、总块数、成功发送块数、响应数、finished 数、最后 `ed`、总耗时、最大单块等待、最大纠正等待、是否完整结束和失败原因。资源监控单独写入按时间采样的 JSONL，不混入接口原始响应。

固定辅助产物名称为：`test/A_summary.json`、`test/B_summary.json`、`test/C_summary.json`，`test/A_monitor.jsonl`、`test/B_monitor.jsonl`、`test/C_monitor.jsonl`，`test/AB_compare.jsonl`、`test/AC_compare.jsonl`、`test/BC_compare.jsonl` 和 `test/full_test_summary.json`。远端服务日志另存为 `test/remote_asr_online.log`。

### 卡死和性能监控

测试客户端必须记录每个音频块的发送时间、对应响应接收时间和最近进度；远端同时采样服务 PID、RSS、GPU 显存、GPU 利用率、进程状态、8084 端口和应用日志。watchdog 采用“无响应窗口 + 全局测试上限”双重保护：有持续进度时允许完整跑完，不因为处理速度慢而主动截断；单路超过无响应阈值时记录最近块、最近响应、服务日志和资源快照，并标记该路为 `stalled`，避免无限等待。出现连接关闭、ASGI 异常、OOM 或进程消失时立即保留现场并结束该路，其他路继续完成或独立标记。

### A/B/C 对比指标

生成三个独立的对比 JSONL 和汇总 JSON：

- AB：对比 v1.0.1 原始在线结果与 v1.0.2 纠正结果，重点看纠正增删改字、标点、finished 段落边界和最终文本覆盖。
- AC：对比 v1.0.1 与 v1.0.3 SenseVoice 结果，重点看 SenseVoice 自带标点、同音字修复和断句延迟。
- BC：对比 v1.0.2 Paraformer 纠正与 v1.0.3 SenseVoice 纠正，重点看相同时间区间的文本差异、纠正稳定性和模型耗时。

每组比较至少包含：按时间重叠匹配的段数、文本 equal/insert/delete/replace 数量、纠正字符位置、finished 数量、相邻段时间重叠、时间倒退、时间空洞、重复文本、最后覆盖到的音频时间、首次/平均/最大 finished 延迟和每个接口的响应间隔分布。结果必须区分“接口协议字段正确”与“识别文本质量更好”，不能只按文本长度判断效果。

### 服务关闭验收

三路测试均完成或被 watchdog 明确终止后，测试流程必须停止 29.12 的 `asr_online` 服务，记录停止前 PID 和退出结果，并确认 8084 不再监听。若服务无法关闭，测试报告必须记录残留 PID、端口状态和需要人工处理的命令，不得把测试标记为完全成功。

## Open Questions

- 1000 ms 与 1200 ms 哪个作为最终生产默认值，需要用相同音频对自然停顿召回率和误切率进行对比后确定。
- pending PCM 的最大保留时长是否采用 3 秒，还是依据最长允许 pre-roll 和下一个 VAD start 的最大确认延迟确定。
- 纠正模型是否需要最近三个 finished 文本作为文本上下文；这不应改变 finished 事件的即时发送语义。
- 全量测试的无响应阈值和全局上限需要根据现有教师音频单块耗时确定，阈值必须写入测试 summary，不能隐含在客户端默认值中。
