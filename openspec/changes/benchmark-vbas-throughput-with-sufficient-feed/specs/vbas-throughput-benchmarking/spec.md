## ADDED Requirements

### Requirement: VBas 能力基准必须获得持续充足供料
基准系统 SHALL 使用预生成且可校验的真实教师和学生帧直接持续调用三个 VBas 实例，并 MUST 绕过媒体下载、FFmpeg、Kafka、Control 租约和外部网络，使 VBas 有空闲测试槽位时始终存在可立即下发的请求。

#### Scenario: 供料器持续补满目标并发
- **WHEN** 某一 VBas 并发档处于稳态测试且实例完成一个请求
- **THEN** 供料器立即补充下一请求直至恢复目标在途量，并记录补位延迟

#### Scenario: 负载器自身无法维持目标并发
- **WHEN** 负载器 CPU、连接池或事件循环导致实际在途量长期低于目标
- **THEN** 当前档 MUST 标记为供料器受限且不得用于宣称 VBas 最高吞吐

### Requirement: VBas 参数必须从受控高位向下收敛
基准系统 MUST 按配置化的高位到低位阶梯分别执行教师、学生和固定比例混合负载，并 SHALL 同时报告最高稳定吞吐档以及达到该吞吐 95% 的最低并发拐点。

#### Scenario: 高位稳定运行
- **WHEN** 高并发档在完整稳态窗口内无错误、无显存持续膨胀且延迟保持稳定
- **THEN** 系统保留该档吞吐、延迟和资源证据并继续执行下一低档以寻找拐点

#### Scenario: 高位触发资源护栏
- **WHEN** 当前档出现 OOM、容器重启、显存越过硬护栏或延迟持续恶化
- **THEN** 系统立即停止该档、保留失败证据并从相同基线执行下一低档

#### Scenario: 两档吞吐近似
- **WHEN** 较低并发档达到已测最高稳定吞吐的 95% 且满足全部稳定性门禁
- **THEN** 较低档 SHALL 作为推荐拐点，较高档仍作为性能极限事实保留

### Requirement: 显存稳定性必须区分预热平台和持续膨胀
基准系统 MUST 分别记录模型就绪、预热结束和稳态阶段的显存时间序列，并 SHALL 根据稳态趋势、显存硬护栏、OOM 和容器重启判定显存是否持续膨胀，不得仅以显存高于启动基线判定泄漏。

#### Scenario: 预热后形成稳定平台
- **WHEN** 显存从模型就绪基线上升后在稳态窗口内形成平台且未越过护栏
- **THEN** 系统将该档记录为显存稳定并报告平台值和峰值

#### Scenario: 稳态阶段继续增长
- **WHEN** 显存在预热后仍持续正向增长、后半段显著高于前半段或触发分配失败
- **THEN** 当前档 MUST 判定为显存不稳定且不得成为推荐参数

### Requirement: 媒体供料和租约分发必须独立测量
验证系统 SHALL 分别执行不调用 VBas 的纯媒体供料基准和不运行 FFmpeg 的预抽帧租约分发基准，并 MUST 使用 ready queue、租约和 HTTP 时间戳区分供料不足与分发不足。

#### Scenario: ready queue 不足且 VBas 空闲
- **WHEN** VBas 存在空闲离线槽位且可下发 ready batch 少于空闲槽位
- **THEN** 对应空档归因为媒体或视觉命令供料不足，不归因为 VBas 路由

#### Scenario: ready queue 充足但 VBas 空闲
- **WHEN** ready queue 中至少存在足以填满全部空闲槽位的 batch，但槽位未在目标补位时间内被使用
- **THEN** 对应空档归因为租约、分发或 Consumer，并报告各阶段等待时间

#### Scenario: 媒体高位出现资源争用
- **WHEN** 降低活动媒体流后 `prepared batch/s` 上升或尾延迟下降
- **THEN** 报告 MUST 将原高位标记为主机资源过度调度，并以实测拐点而不是 CPU 核数推导推荐值

### Requirement: 完整链路验收必须复用隔离基准结论
完整视觉链路 SHALL 使用固定课程 fixture、全新任务 ID 和隔离阶段得到的候选参数执行对照测试，并 MUST 同时验证任务成功、VBas 槽位利用率、空档归因、显存平台和 Consumer 健康。

#### Scenario: 候选参数持续供满 VBas
- **WHEN** ready queue 持续具有足量 batch 且完整链路运行候选参数
- **THEN** 三实例同时空闲比例低于 10%、平均活跃槽位不低于 `4.8/6`，所有实例均持续参与且无实例饥饿；相同型号 GPU 的完成量差异不超过 10%，异构 GPU MUST 按实际服务时间、槽位活跃度和能力比例评估而不得强制 batch 数均分

#### Scenario: 完整链路仍然供料不足
- **WHEN** 裸 VBas 和预抽帧分发基准均达到目标，但完整链路 ready queue 经常为空
- **THEN** 结论 MUST 明确归因为视觉命令启动或媒体抽帧，禁止继续通过提高 VBas 容量掩盖问题

### Requirement: 基准证据必须完整且可重放
每轮基准 MUST 固化 Git SHA、镜像 ID、有效配置、fixture manifest、随机种子、时间窗口、原始指标、退出状态和中文结论；中断、护栏停止或缺失证据的运行 MUST 保持未通过。

#### Scenario: 相同候选参数重复验证
- **WHEN** 推荐参数完成至少两轮相同输入和环境的重复测试
- **THEN** 两轮吞吐偏差默认不超过 5%，否则继续保留为未收敛状态

#### Scenario: 测试在终态前中断
- **WHEN** runner、容器或采集器在完整稳态窗口和证据落盘前终止
- **THEN** 当前 attempt 标记为中断且不得依据后续任务排空补写通过
