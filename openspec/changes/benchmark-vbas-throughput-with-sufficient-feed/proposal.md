## 背景与动机

当前完整视觉链路中三台 VBas 的平均离线槽位利用率仅约 `0.70/6`，但现有证据同时混合了视觉命令启动、FFmpeg 抽帧、租约分发和 VBas 推理，无法严格证明 VBas 的最高稳定处理能力，也无法量化供料是否足以持续填满全部实例。需要建立一套“上游供料充足、从高并发向下收敛”的隔离基准，找出吞吐最高且显存不持续膨胀的 VBas 参数，并用完整链路验证供料效率。

## 变更内容

- 建立可重复的 VBas 裸能力基准，使用预生成真实帧绕过下载、FFmpeg、Kafka 和 Control 租约，分别测量教师、学生及混合负载。
- 采用高位起测、阶梯下降、拐点复测的方法搜索单实例 `MaxConcurrentOfflineBatches`；测试上界由显存和错误护栏约束，而不是配置类型允许的理论最大值。
- 建立纯媒体供料基准，允许测试阶段充分使用 CPU 和内存，不预先限制 FFmpeg 资源；分别量化视觉命令启动、抽帧生产和 ready queue 供给能力。
- 建立预抽帧后的真实租约与分发基准，用于区分“有帧但没有及时下发”和“根本没有准备好帧”两类空档。
- 为每轮测试固化配置、fixture、镜像 revision、时间窗口、吞吐、延迟、显存、GPU 利用率、队列和租约证据，并生成中文 Harness 报告。
- 使用隔离阶段得出的候选参数执行完整视觉链路回验；未完整执行、提前中断或缺失原始证据的测试不得记为通过。
- 不改变 A 服务北向接口、VBas HTTP 请求响应、视觉业务规则、四服务边界和现有节点状态码。

## 能力范围

### 新增能力

- `vbas-throughput-benchmarking`：定义在供料充足前提下测量 VBas 极限吞吐、显存稳定性、供料能力、分发效率和参数收敛的可重复验证合同。

### 修改能力

无。现有主规范尚未定义 VBas 容量基准和视觉供料效率的验收要求，本次新增独立能力。

## 影响范围

- 测试与 Harness：`algorithm-scheduling-platform/tests`、负载工具、指标采集脚本及 Harness 证据目录。
- 视觉平台：可能补充 `vision_orchestrator_service` 的低基数阶段指标和测试替身接入点，但不改变生产请求合同或聚合结果。
- VBas：复用现有教师、学生接口和配置项进行压测；不修改模型推理语义。
- 运行环境：在 `192.168.29.11` 的三张 GPU、三个 VBas 实例和 Vision 容器上执行；使用相同镜像 revision、固定图片/视频 fixture 和受控测试窗口。
- 兼容性：不影响 A 服务提交、查询和在线网关调用；不要求 A 服务新增字段。
