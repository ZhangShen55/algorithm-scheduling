## Context

当前 `asr_online` 使用 FunASR 在线 Paraformer，每约 480 ms 处理一个 PCM 块，返回本次增量文字。服务端将增量文字追加到 `buffer`，并使用“连续两个块没有新文字”近似判断语音结束；这不是可靠的 VAD，也没有完整语音段重识别和结果修订能力。

本变更只针对 `asr_online`，新增 `/v1.0.2/seacraft_asr_online`。`/v1.0.1/seacraft_asr_online`、`online_gateway_service`、现有上行 PCM 格式和既有基础响应字段必须保持不变。当前本地验证使用 `asr` Conda 环境和 CPU，后续再验证 GPU。

## Goals / Non-Goals

**Goals:**

- 提供与 v1.0.1 隔离的 v1.0.2 WebSocket 入口。
- 保持 v1.0.2 的请求方式和基础响应字段兼容。
- 支持同一语音段的临时文本被最终文本覆盖。
- 在句末保留完整 PCM，并为后续 VAD、`is_final=True` 冲刷和二遍 ASR 留出清晰的会话状态边界。
- 用真实课堂音频完成 CPU 端到端验证，并保存结果。

**Non-Goals:**

- 本次不修改 v1.0.1。
- 本次不修改 `online_gateway_service` 或平台路由。
- 本次不承诺在语音尚未结束时进行滑动窗口重识别。
- 本次不引入 LLM 文本改写，不改变原始语义。
- 本次不完成 GPU 性能调优；GPU 只在后续阶段验证。

## Decisions

### 1. 新增独立路由，内部逻辑可复用

v1.0.1 和 v1.0.2 使用独立的 WebSocket 入口，底层可共享模型访问和工具函数。v1.0.2 的会话处理函数通过版本入口调用，后续修订逻辑只在 v1.0.2 分支演进。选择新增路由而不是修改原路由，便于灰度、回退和对比测试。

备选方案是复制整份处理代码，隔离更彻底但会造成长期修复分叉；因此只隔离入口和版本策略，不复制模型加载代码。

### 2. 保留基础 JSON 字段，使用固定 `key` 表达覆盖关系

v1.0.2 继续返回 `key`、`text`、`finished`、`bg`、`ed`。一个语音段在生命周期内使用一个稳定的 `key`：`finished=false` 表示临时结果，`finished=true` 表示最终结果。客户端按 `key` 覆盖同一段文本，而不是逐条追加。

备选方案是新增独立 correction 消息类型，表达更明确但会扩大协议变化；当前先使用已有字段承载，后续如需要再增加可选字段。

### 3. 句末以 VAD/会话边界为准，标点只做文本后处理

标点模型不得单独决定 `finished`，因为临时识别中的标点可能被后续上下文改变。句末应由 VAD 或明确的会话结束事件决定，随后对完整 PCM 做最终处理。

### 4. 两遍识别作为后续纠正路径

在线 Paraformer 负责低延迟临时输出；语音段结束后，使用完整 PCM 调用离线高精度 ASR，再进行标点和格式化，最终覆盖临时结果。该方式复用现有 FunASR 生态，准确率和实现复杂度适合当前项目。

## Risks / Trade-offs

- [临时文本可能被覆盖] → v1.0.2 文档和测试明确 `key` 的段级覆盖语义；v1.0.1 保持旧行为。
- [CPU 二遍识别增加句末延迟] → 先在 CPU 测通正确性，记录端到端耗时；GPU 阶段再评估并发和显存。
- [VAD 边界错误导致句首/句尾丢字] → 保留边界上下文，句末调用在线模型 `is_final=True`，并使用真实音频验证。
- [v1.0.2 直接测试而网关仍指向 v1.0.1] → 本阶段只使用算子直连地址，明确网关接入留到后续变更。
- [现有模型目录可能不包含离线纠正模型] → 第一阶段先完成隔离接口和基础行为；启用二遍识别前检查模型路径、显存/内存和依赖。

## Migration Plan

1. 新增 v1.0.2 路由并确认它与 v1.0.1 基础行为一致。
2. 在 CPU 上通过 `compileall`、导入检查、项目测试和真实 WAV WebSocket 测试。
3. 在 v1.0.2 内逐步启用 VAD、PCM 句段缓存、二遍识别和稳定 `key`。
4. 对比 v1.0.1 与 v1.0.2 的实时延迟、句末延迟、最终文本和资源占用。
5. 后续单独修改 `online_gateway_service` 增加 v1.0.2 网关入口；失败时网关继续使用 v1.0.1。

## Open Questions

- 上游展示端当前是否已经按 `key` 覆盖临时字幕，还是收到消息后直接追加？这决定 v1.0.2 是否需要兼容适配消息。
- 二遍识别使用 `asr_offline` 现有离线模型，还是为在线服务准备一份独立模型副本？
- VAD 句末静音阈值和保留上下文长度需要通过课堂音频测试确定。
