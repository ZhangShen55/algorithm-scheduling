# ASR Offline Docker 部署说明

本文供有 NVIDIA GPU 的 Linux 服务器运维人员使用。镜像已包含 ASR 模型和运行时依赖，部署从 `docker load -i` 导入 tar 包开始。本文只部署单个离线 ASR 实例，不包含算法调度平台、Kafka 或 Redis。

## 1. 部署约束

- 宿主机需为 x86_64 Linux，已安装 Docker Engine、NVIDIA 驱动和 NVIDIA Container Toolkit。
- 每个容器只使用一张宿主机 GPU。下文选择物理 GPU `0`；Docker 会将其重编号为容器内 GPU `0`，因此 `config.toml` 必须使用 `device = "cuda:0"`。
- 模型已在镜像 `/app/model` 中，不要挂载宿主机模型目录覆盖它。
- 服务端口是 `8083`，唯一离线转写路由是 `POST /v1.1.8/seacraft_asr`。
- 镜像固定以一个 Uvicorn worker 运行，不需任何启动环境变量。

## 2. 部署前检查

在宿主机执行：

```bash
docker version
nvidia-smi
```
两条命令必须成功。导入交付镜像后再按第 4 节的命令验证 Docker 容器的 GPU 透传，避免在离线网络中依赖拉取公网镜像。

## 3. 准备配置和持久化目录

以 `/opt/seacraft/asr-offline` 作为宿主机运行目录：

```bash
sudo install -d -m 0755 /opt/seacraft/asr-offline/config
sudo install -m 0644 /path/to/asr_offline.gpu.toml \
  /opt/seacraft/asr-offline/config/config.toml
```
随交付包使用 GPU 版 `asr_offline.gpu.toml`。关键配置如下：

```toml
device = "cuda:0"

[features]
open_spk = true
open_emotion = true
open_mul_lang = true
```
不要添加 `ngpu`、`ncpu`、`compute_type`、`log_path` 或 `hotword_path`。程序会根据 `device` 为 GPU 模型自动传递 `ngpu=1`，Whisper 固定使用 `int8`。日志自动创建在容器项目目录的 `/app/logs/asr_service.log`，保留当日与前 6 个日志归档。

## 4. 导入离线镜像

将 tar 包放到服务器后执行：

```bash
sudo docker load -i /srv/releases/seacraft-asr-offline.tar
sudo docker image ls --format 'table {{.Repository}}\t{{.Tag}}\t{{.ID}}\t{{.CreatedSince}}'
```

`docker load` 会输出 `Loaded image: <repository>:<tag>`。将它的完整值设为本次发布的镜像引用：

```bash
export IMAGE_REF='<repository>:<tag>'
sudo docker image inspect "$IMAGE_REF" \
  --format 'image={{.RepoTags}} id={{.Id}} created={{.Created}}'
sudo docker run --rm --gpus '"device=0"' \
  --entrypoint /bin/bash "$IMAGE_REF" -lc 'nvidia-smi'
```
第三条命令必须显示被分配的 GPU 0 和驱动版本。如果失败，先修复 NVIDIA Container Toolkit，不要继续启动 ASR 容器。不要根据 tar 文件名推断镜像标签，必须以 `docker load` 输出为准。请在发布记录中保存 `IMAGE_REF`、导入时间、Git SHA 和供应方提供的镜像摘要。

## 5. 启动容器

端口映射到宿主机所有网卡，供上游调度服务访问：

```bash
sudo docker rm -f asr-offline 2>/dev/null || true

sudo docker run -d \
  --name asr-offline \
  --restart unless-stopped \
  --gpus '"device=0"' \
  -p 8083:8083 \
  -v /opt/seacraft/asr-offline/config/config.toml:/config.toml:ro \
  "$IMAGE_REF"
```
必须在防火墙或安全组中仅放行所需的上游网段。不要使用 `--privileged`、`--network host` 或 `--ipc host`。如果一台宿主机需运行多个 ASR 实例，每个实例必须使用不同的物理 GPU、端口、容器名称和配置文件。每个容器内的 `device` 仍为 `cuda:0`。

## 6. 启动验收

等待模型加载完成后执行：

```bash
until curl -fsS http://127.0.0.1:8083/ops/health; do sleep 2; done
curl -fsS http://127.0.0.1:8083/get_status | jq .
curl -fsS http://127.0.0.1:8083/openapi.json \
  | jq -e '.paths | has("/v1.1.8/seacraft_asr") and has("/audio/db_snr")'
sudo docker ps --filter name=^/asr-offline$ \
  --format 'table {{.Names}}\t{{.Status}}\t{{.Image}}\t{{.Ports}}'
sudo nvidia-smi
sudo docker exec asr-offline ls -lh /app/logs/asr_service.log
```
预期：`/ops/health` 返回 HTTP 200，`/get_status` 的 `appVersion` 为 `asr:latest`，OpenAPI 含有 `/v1.1.8/seacraft_asr` 和 `/audio/db_snr`，容器内日志文件已生成。

使用已获授权的短音频做转写验收：

```bash
curl -fsS -X POST http://127.0.0.1:8083/v1.1.8/seacraft_asr \
  -F 'audioFile=@/srv/fixtures/asr-smoke.wav;type=audio/wav' \
  -F 'language=zh' \
  -F 'showSpk=false' \
  -F 'showEmotion=false' \
  -F 'showRoleIdentify=false' \
  -F 'wordTimestamps=false' \
  | jq -e '(.text | length) > 0 and (.segments | length) > 0'
```

## 7. 运维、升级与回滚

查看控制台和容器内部文件日志：

```bash
sudo docker logs --tail 200 -f asr-offline
sudo docker exec -it asr-offline sh -lc 'tail -n 200 -f /app/logs/asr_service.log'
```

常用操作：

```bash
sudo docker restart asr-offline
sudo docker stop asr-offline
sudo docker start asr-offline
sudo docker inspect asr-offline --format '{{.State.Status}} {{.State.ExitCode}} {{.State.Error}}'
```
如果启动失败，先执行 `sudo docker logs asr-offline` 和 `sudo nvidia-smi`。使用 `device="cuda:0"` 时，GPU 或 CTranslate2 不可用会阻止模型初始化，这是预期保护行为。

升级前记录当前镜像，不要删除容器外的配置目录。日志位于容器内，重建容器后会从新累积：

```bash
export PREVIOUS_IMAGE="$(sudo docker inspect asr-offline --format '{{.Config.Image}}')"
sudo docker load -i /srv/releases/seacraft-asr-offline-next.tar
sudo docker image ls --format 'table {{.Repository}}\t{{.Tag}}\t{{.ID}}'
export NEXT_IMAGE='<next-repository>:<next-tag>'
sudo docker rm -f asr-offline
```
然后使用第 5 节完全相同的 `docker run` 参数启动 `$NEXT_IMAGE`，并完成第 6 节验收。如果验收失败，删除新容器后以同样参数启动 `$PREVIOUS_IMAGE`。只要不执行 `docker image rm "$PREVIOUS_IMAGE"`，回滚镜像就会保留。

## 8. 常见故障

| 现象 | 检查与处理 |
| --- | --- |
| 容器立即退出，提示配置不存在 | 确认宿主机配置存在，并精确挂载到 `/config.toml:ro`。 |
| CUDA 或 CTranslate2 不可用 | 先运行第 2 节的 `nvidia-smi` 和第 4 节的交付镜像 GPU 透传检查；同时检查 `--gpus '"device=0"'` 与 `device="cuda:0"`。 |
| 健康检查长时间不就绪 | 首次启动会加载 ASR、说话人、情感和 Whisper 模型。用 `docker logs -f asr-offline` 观察；进程退出时以第一个 `ERROR` 为准处理。 |
| 端口不可访问 | 端口已绑定宿主机所有地址，检查 `docker ps`、宿主机防火墙和安全组的 `8083/TCP` 放行范围。 |
| 法语请求返回业务码 `4003` | 确认 `[features].open_mul_lang=true`，且 `whisper_model_dir` 仍指向镜像内的模型路径。 |
| 需要查询详细日志 | 使用 `docker exec -it asr-offline sh -lc 'tail -n 200 -f /app/logs/asr_service.log'`。注意重建容器会清空该文件日志。 |
