## 背景

当前处理链路只解码视频关键帧并比较相邻画面及上一张已保存图片。该规则能处理静态 PPT 换页，但没有跨时间窗口的状态，持续播放视频、连续滚动或短暂停顿会反复满足“稳定且与上次保存不同”，产生大量无业务价值的图片。

首个已知验收视频总时长约 `3300.107s`，用户标注的播放视频区间约为 `[2368000,2627000)` 毫秒，即 `39:28-43:47`。同时，课程目录 `http://192.168.29.12:5555/course/` 包含多门课程及嵌套目录。提案阶段的一次只读发现得到 40 个目录页、37 个文件名包含 `PPT` 的 `.mp4`；该数字只是当次观察值，实施和每轮验收必须重新发现并冻结清单，不能把 37 写死。

用户希望持续优化到这些课程中疑似播放视频或持续滚动片段都能准确识别。工程上无法证明未来未知视频绝对零错误，因此设计把目标限定为：当前冻结且可访问语料全部执行、全部候选得到复核、漏报检查完成，并达到指标门槛且无已知误报或漏报。

## 目标 / 非目标

**目标：**

- 使用视频时间戳和滚动窗口识别持续动态区间，而不是用单次帧比较直接判定。
- 正常 PPT 换页、短动画和小范围鼠标移动仍能在稳定后生成一张代表图。
- 已确认动态区间内不发布 PPT 切片，动态结束后恢复正常切片。
- 输出排序、互不重叠的毫秒区间，保持现有任务提交、共享目录和一次终态回调兼容。
- 自动发现课程目录中的全部 P 视频，冻结每轮语料快照并支持断点续跑。
- 为候选区间和漏报检查生成可回看的证据，建立人工/AI 复核真值及中文报告。
- 隔离校准集和保留验证集，记录版本、配置、性能与准确性，形成可重复的算法迭代闭环。

**非目标：**

- 第一版不理解课程语义，不识别人物、字幕或播放内容主题。
- 第一版不承诺精确区分全屏视频、PPT 内嵌视频和滚动页面；对外可统一为 `SUSPECTED_VIDEO_PLAYBACK`，复核报告可记录更细标签。
- 不引入深度学习模型、GPU 推理、Kafka 或数据库依赖。
- 不在本变更中修改 orchestrator 的数据库结果模型或 A 服务查询接口。
- 远程课程 MP4 只允许通过 URL 流式探测和解码，不落盘原始视频、完整副本或 MP4 预览；切片、证据图片和解码特征也不得提交 Git。

## 设计决策

### 1. 动态检测和 PPT 去重使用独立阈值

请求中的 `threshold` 继续表示“稳定页面与上一张已保存 PPT 是否足够不同”。动态检测使用独立配置，包括采样间隔、活动变化阈值、活动区域比例、确认时长和退出稳定时长，避免改变已有 PPT 去重语义。

每个观测点至少包含：

- 基于 `pts * time_base` 得到的 `timestamp_ms`；
- 与上一观测帧的像素变化比例；
- 将画面划分为网格后发生有效变化的区域比例；
- 当前稳定连续时长和滚动窗口内的活动观测比例。

网格活动比例用于忽略鼠标指针等极小区域变化，也为后续识别局部内嵌视频保留数据。第一版优先使用低成本像素和网格时序特征；只有冻结语料给出明确漏报证据时，才以独立可配置特征增加方向一致性或光流，不能为了一个样本直接引入复杂模型。v6 的全量校准漏报审计已经提供该证据，因此 v7 按下述“只保活、不触发”边界增加光流。

首轮已知样本复核在 `54:52-54:59` 发现一段约 7 秒的网页持续滚动。旧关键帧观测在该段只有约 3 个有效点，虽被近阈值漏报检查捕获，但无法满足动态确认窗口。继续降低活动阈值会扩大普通换页误报，因此动态检测开启时改为解码参考帧，并在进入切片流水线前按 `sample_interval_ms` 固定时间限频；动态检测关闭时仍只解码关键帧，恢复旧流程。该策略不下载或落盘视频。

### 2. 使用视频时间戳驱动四态状态机

状态机为：

```text
STABLE
  │ 持续出现活动观测
  ▼
DYNAMIC_CANDIDATE
  ├─ 很快恢复稳定 ──▶ STABLE（普通换页或短动画）
  └─ 达到确认时长 ──▶ DYNAMIC
                            │ 连续稳定达到退出时长
                            ▼
                       STABILIZING
                         ├─ 再次活动 ──▶ DYNAMIC
                         └─ 稳定确认 ──▶ STABLE
```

- 进入 `DYNAMIC` 时，起点回看至本轮连续活动的首个观测时间，而不是确认时刻。
- `DYNAMIC` 中允许短暂停顿；只有连续稳定达到退出时长才结束。
- 区间采用半开形式 `[start_ms,end_ms)`，结束点取退出前持续稳定片段的起点。
- 文件结束时仍处于动态状态，使用最后一个有效时间戳关闭区间。
- 相邻动态段间隙小于等于配置值时合并，避免短暂停顿把一段播放内容切碎。

初始值只作为校准起点：采样间隔 `1s`、动态确认 `5s`、滚动窗口 `8s`、活动观测比例 `0.7`、退出稳定 `3s`。已知播放样本中连续视频因静态镜头产生最长约 17 秒的检测间隙，因此短间隙合并校准为 `20s`。

完整校准集 `20260807-calibration-v5` 进一步证明，教学视频可能包含超过 20 秒、甚至约 60-70 秒的长静止镜头。仅把全局短间隙阈值增大到 90 秒会吞掉“动态内容结束后出现的正常稳定 PPT”，因此增加第二层“连续动态簇”规则：

- 先按 `merge_gap_ms=20s` 合并普通短暂停顿；
- 再把相邻间隔不超过 `cluster_gap_ms` 的段组成候选链；
- 只有候选链达到 `cluster_min_segments` 才扩展为覆盖首段起点到末段终点的动态簇；
- 默认校准起点为 `cluster_gap_ms=90s`、`cluster_min_segments=3`，必须通过校准集、保留集和最终全量复核验证；
- 不足最小段数的候选链保持原始短间隙合并结果，不能仅因出现一到两次动态内容而吞掉中间正常 PPT。

该双层规则解决 v5 已知的部分长静止镜头漏报，同时把对普通 PPT 的影响限制在有重复动态证据的时间范围内。

v6 完整校准及漏报审计又发现：航空低运动镜头、竖屏视频和莎士比亚长片中仍存在大量像素变化比例不足的画面。它们会让状态机在 3 秒后退出，后续强活动段之间的间隔有时超过 90 秒，不能继续依靠扩大聚簇间隔解决。v7 增加可关闭的稠密光流“动态保活”特征，但遵守以下约束：

- 强像素/网格活动是从 `STABLE` 创建动态候选的唯一依据；进入候选前的稳定观测不得污染本轮确认窗口；
- 光流活动不能单独创建动态候选，但可以延续已由强活动创建的 `DYNAMIC_CANDIDATE` 并参与持续时间/活动比例确认，也可以让已确认的 `DYNAMIC`/`STABILIZING` 状态继续保持；
- 光流在缩小画面上计算，以运动像素覆盖比例过滤鼠标等局部变化；
- 只有当最后一次有效信号是弱光流时，才在后续无强活动且无光流的阶段使用可配置光流宽限时间；若最后是强像素/网格活动，仍按 `exit_stable_ms` 退出，区间终点都回看至真正稳定开始时间；
- 该策略避免普通 PPT 换页或渐进动画仅凭光流触发“疑似视频”，同时覆盖电影静止镜头中的细微人物、字幕和摄影机运动。

v7 定向验证证明光流仍不能覆盖所有课程录屏：莎士比亚 `16:45` 的外部播放器在约 `1759s` 起播后长时间重复相同帧，光流只能确认 `1767806-1793098ms`。尝试以 `300s + 6 个强证据` 形成长会话时，又把 `15:55` 课程误合并为 `12180-2680721ms`，几乎吞掉整节课。该时间聚簇方案已撤回。

上述证据表明，仅依靠像素差、光流和时间间隔无法同时满足这批语料的零已知误报/漏报目标。继续校准前需确认新的架构输入：由上游提供播放区间，或在本服务引入能区分 `PPT_SLIDE` / `VIDEO_PLAYER` / `DESKTOP_OTHER` 的画面语义分类。在选定前，不得通过继续放大聚簇间隔声称问题已解决。

### 3. 候选切片延迟发布

当前立即写图无法在动态确认回看或连续动态簇确认后撤销。新流程只保留有限数量的候选帧、时间戳和指标：

- 候选所在时间窗被确认为动态时，直接丢弃，不创建 `.part` 或最终 JPEG。
- 第一段动态结束后，在 `cluster_gap_ms` 范围内产生的候选切片先保留为内存中的 JPEG 字节和元数据；候选链达到 `cluster_min_segments` 时丢弃簇内候选，候选链超时且未成簇时再发布正常 PPT。
- 短间隔合并或光流保活不得丢失独立强活动爆发数；聚簇判断使用强活动证据总数，而不是压缩后的最终段数。该证据数仅供内部聚簇，不扩展对外区间字段。
- 内存缓冲只覆盖尚未决议的尾部候选链；候选链完成或超时后立即释放，不能缓存完整视频、完整帧序列或源 MP4。
- 活动很快结束且画面达到 PPT 稳定时长时，才原子写入最新稳定候选。
- 动态结束后，画面重新通过稳定确认才保存新的 PPT 页面。

该方式不批量缓存全分辨率视频帧，也不依赖删除已经对外可见的文件。内存上限由固定候选数量和缩小后的分析帧控制。

### 4. 结果以可选字段兼容扩展

`manifest.json` 增加：

```json
{
  "dynamic_segments": [
    {
      "type": "SUSPECTED_VIDEO_PLAYBACK",
      "start_ms": 2368000,
      "end_ms": 2627000,
      "confidence": 0.91,
      "reason": "sustained_visual_change"
    }
  ]
}
```

约束：

- `start_ms < end_ms`，按起点升序且互不重叠；
- `confidence` 位于 `[0,1]`，由活动比例、持续时长和有效观测覆盖计算；
- `count` 只统计切片图片，不统计动态区间；
- 终态回调携带同一列表，不包含图片二进制；
- 没有动态内容时返回空列表；失败任务可返回停止前已确认区间，既有失败状态保持不变。

`schema_version` 暂保持 `1`。现有 orchestrator 可忽略额外字段；平台消费和持久化该字段属于另一个变更。

### 5. Harness 分离长期规则、变更事实和大体积证据

项目新增以下轻量结构：

```text
harness/
├── README.md
├── architecture-review.md
├── change-ledger.md
├── verification.md
├── scenarios/
│   └── dynamic-video-corpus.md
└── reports/
    └── <run_id>/
        ├── inventory.json
        ├── segments.json
        ├── segments.csv
        └── 疑似动态区间复核报告.md
```

- `AGENTS.md` 只记录持久边界：OpenSpec 管需求设计、Harness 管变更证据、远程视频不得入库、全量语料和复核未完成不得宣称通过。
- `change-ledger.md` 记录每轮算法版本、配置摘要、变更原因和关联报告。
- `verification.md` 记录可复现命令、环境、成功与失败；不能只记录最终成功。
- `reports/` 中可提交小型 JSON/CSV/Markdown 摘要；证据帧、联系表和特征缓存放在 Git 忽略目录，报告只保存稳定相对路径和校验信息。Harness 不生成视频预览文件。

这样既能审计变化，也不会让 `AGENTS.md` 变成流水账或把大量课程数据提交到仓库。

### 6. 每轮递归发现并冻结语料清单

发现器从 `/course/` 起点递归遍历同源目录链接，只纳入 basename 包含 `PPT` 且扩展名大小写不敏感等于 `.mp4` 的文件。必须规范化并去重 URL，禁止越出允许的 host 和路径前缀。

每轮 `inventory.json` 至少保存：

- 规范化 URL 与解码后的课程/文件名；
- `Content-Length`、`Last-Modified` 或可获得的等价资源指纹；
- `duration`、codec、fps、分辨率；
- 发现、探测、处理和复核状态及错误原因；
- 本轮 `run_id`、发现时间和工具版本。

每轮开始冻结清单，运行期间目录新增内容不改变本轮分母，下一轮重新发现时自动纳入。当前观察到的 37 个视频只能作为初始核对值，不能成为代码常量。

### 7. 可恢复的全量运行与证据生成

全量 runner 直接把远程 URL 交给 `ffprobe`/PyAV 或 FFmpeg 流式读取，对每个冻结视频执行探测和动态检测，设置并发、超时与重试上限，按视频写检查点。任何路径都不得先下载完整 MP4；中断后只重跑未完成或资源指纹改变的项目；最终正式验收必须在冻结配置下对全部视频重新端到端运行，不能只使用历史特征缓存拼接结果。

每个候选区间生成：

- 起点前后、中点、终点前后的证据帧；
- 一张带时间戳的联系表；需要连续画面复核时，在内存中读取相邻采样帧，不生成 MP4、GIF 或其他视频副本；
- 关联原始 URL、区间时间、算法版本和配置摘要。

缓存和证据默认存放于 Git 忽略的 `harness/.cache/` 与 `harness/artifacts/<run_id>/`。缓存只能包含小型探测元数据、压缩特征和少量静态证据，不得包含 MP4 或完整视频内容。报告中的路径必须足以让用户在本机打开证据并回到原视频相同时间复查。

### 8. 复核候选，同时主动检查漏报

AI 可以基于证据先做辅助复核，但无法判断或证据不足时必须标为 `UNCERTAIN`，不能自动当作真值。候选复核标签为：

- `CONFIRMED_VIDEO`：确认为视频播放；
- `CONFIRMED_SCROLL`：确认为持续滚动或连续页面变化；
- `FALSE_POSITIVE`：正常 PPT、短动画、转场或其他误报；
- `UNCERTAIN`：证据不足，等待人工确认。

只审候选只能计算误报，无法发现漏报。Harness 还必须对算法未报出的时间范围执行确定性漏报检查：至少覆盖固定时间网格、长时间未切片区间、切片异常密集区间、变化分数高但未过阈值区间，并生成同样的证据供复核。所有 `UNCERTAIN` 和疑似漏报必须进入待人工队列。

真值记录与算法原始输出分离，人工修改真值不得覆盖原始检测结果。每条结论保存复核者、时间、证据引用和备注。

### 9. 校准集与保留验证集防止过拟合

用户预先给出真值或实施前已经人工标注的样本固定进入校准集，并以 `split_reason=KNOWN_TRUTH` 记录；其余规范化课程 URL 再按稳定哈希确定性划分，约 70% 为校准集、30% 为保留验证集。同一课程的片段不能跨集合。inventory 指纹包含最终 split，防止划分变化后复用旧检查点。所有视频均会执行，但真正未见的保留集标签和指标在阈值冻结前不得用于调参；只有校准集达到预期后才揭示保留集结果。

若保留集失败，可以回到新一轮设计和校准，但每次必须记录失败配置、原因和变更，不能在同一轮不断查看保留集后声称其仍是未见验证集。必要时按新 `run_id` 重新冻结版本和报告。

### 10. 报告与完成门槛

每轮同时生成 `segments.json`、`segments.csv` 和中文 Markdown。中文表格至少包含：课程、视频 URL、视频时长、疑似开始、疑似结束、类型、置信度、证据位置、复核结论、备注、算法版本和配置摘要。另列目录发现失败、资源不可达、解码失败和未复核条目。

指标至少包括：

- 发现覆盖率与处理完成率；
- 候选复核覆盖率；
- segment precision/recall；
- 时间覆盖 precision/recall；
- 起止边界绝对误差及 p50/p95；
- 每小时误报数、切片抑制数、处理速度和峰值内存。

目标门槛为：冻结语料发现覆盖率 100%，所有可访问视频处理完成，候选和漏报检查复核覆盖率 100%，segment precision/recall 不低于 95%，p95 边界误差不超过 20s，并且最终审阅中没有已知误报或漏报。任何视频不可访问、处理失败或仍为 `UNCERTAIN` 时，报告必须明确为“未完成”或“有阻塞”，不能宣称验收通过。

已知 `39:28-43:47` 样本仍作为强制回归：覆盖率至少 90%，两端误差分别不超过 20s，核心 `[2388000,2607000)` 不产生切片。

## 风险与权衡

- [风险] 静态镜头较长的视频可能被误认为 PPT → 结合持续活动、短暂停顿合并和漏报检查，不能仅凭某一秒静止退出。
- [风险] 数字板书或逐步动画被误判为动态 → 要求持续时间和活动区域比例，并在复核报告中单列误报类型。
- [风险] 只观察关键帧会漏掉短持续滚动 → 动态检测开启时解码参考帧并按固定时间间隔限频；关闭时保留旧关键帧回滚路径，同时记录处理速度和内存变化。
- [风险] 内网目录变化或暂时不可用破坏可重复性 → 每轮冻结 URL 和资源指纹，失败单列且不计通过。
- [风险] AI 视觉复核把不确定判断伪装成真值 → 强制 `UNCERTAIN` 标签和人工待办，保留证据及复核者。
- [风险] 对 37 个当前样本反复调参产生过拟合 → 课程级稳定哈希拆分校准/保留集，并记录每次揭示保留集后的新一轮。
- [风险] 全量视频反复流式解码成本高 → 可缓存探测信息和中间特征用于开发迭代，但禁止用下载完整 MP4 换取速度，最终验收必须完整端到端重跑。
- [风险] “准确无误”被理解为对未来数据永久 100% → 完成声明始终绑定 `run_id`、冻结清单、算法版本和已复核真值。
- [权衡] 第一版对外统一 `SUSPECTED_VIDEO_PLAYBACK` → 先稳定解决无效切片；更细分类只在复核报告中使用，待数据证明必要后再升级契约。
