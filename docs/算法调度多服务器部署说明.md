# 算法调度多服务器部署说明

## 结论

当前控制台可以部署在任意一台能访问观测接口的服务器上。前端只保存并使用以下地址：

- Control Service 地址
- online-gateway-service 地址
- GPU 指标容器地址

PostgreSQL、Redis、Kafka 不需要暴露给浏览器，也不应该在前端配置。它们由 Control Service、Orchestrator 和 Vision Orchestrator 通过各自容器环境变量连接，前端只读取服务聚合后的状态。

## 多服务器拓扑

```text
浏览器
  |
  +--> algorithm-scheduling-ops-console :5174
  +--> Control Service                  :18100 ----> PostgreSQL / Redis
  +--> online-gateway-service           :18103 ----> 算子实例
  +--> GPU exporter                     :9400  ----> 当前 GPU 主机的全部 GPU
                                      \
                                       +--> Orchestrator / Kafka
```

上图中的 GPU exporter 是“单台主机级”采集器。它通过 NVIDIA Container Toolkit 读取所在主机的 GPU，因此一台 GPU 服务器部署一个 exporter 容器；不同 GPU 服务器不能由当前单个 `gpuBaseUrl` 同时覆盖。

## 推荐部署方式

### 方案 A：一台 GPU 主机

保持当前方式：在 GPU 主机启动一个 `gpu-metrics-exporter`，控制台中配置该主机的 `http://IP:9400`。实例清单通过实例的 `gpu` 标签或实例 ID 显示本机 GPU 上部署的算子。

### 方案 B：多台 GPU 主机，最小改动

每台 GPU 主机运行一个 exporter，例如：

```text
GPU 主机 A -> http://10.0.0.11:9400
GPU 主机 B -> http://10.0.0.12:9400
GPU 主机 C -> http://10.0.0.13:9400
```

后续最小前端扩展是把“GPU 指标容器地址”从单个地址改成地址列表，并给每个地址增加主机名。页面合并展示时使用 `host_id + gpu_index` 作为唯一键，避免不同主机的 `GPU 0` 冲突；实例映射同时要求实例注册信息带 `host_id` 和 `gpu` 标签。这个扩展只影响 GPU 展示和配置，不影响 Control Service、Gateway、A 服务或算子协议。

### 方案 C：增加 GPU 聚合器

在平台观测网络增加一个 GPU 聚合服务，由聚合器访问各主机 exporter，向前端统一提供 `/gpu` 和 `/metrics`。这是更适合长期运行的方式，前端继续只配置一个地址，但需要处理主机离线、采集超时、重复 GPU 编号和聚合时间戳。

## PostgreSQL、Redis、Kafka 分机部署

分机部署可以支持，关键是修改平台服务容器的连接环境变量和网络连通性：

| 组件 | 由谁连接 | 配置位置 | 前端是否直连 |
| --- | --- | --- | --- |
| PostgreSQL | Control / Orchestrator / Vision | 各服务 `*_POSTGRES__DSN` | 否 |
| Redis | Control Service 等使用方 | 各服务 `*_REDIS__URL` | 否 |
| Kafka | Orchestrator / Vision / 发布链路 | 各服务 `*_KAFKA__BOOTSTRAP_SERVERS` | 否 |
| GPU exporter | 浏览器和后续 Prometheus | 控制台 GPU 地址 | 是，只读 |

Kafka 的 `advertised.listeners` 必须对实际客户端发布可达地址；不能只发布 Docker 内部的 `kafka:29092`。PostgreSQL、Redis 和 Kafka 的端口只需要对对应平台服务网段开放，并配置防火墙、账号和密码。前端页面不应保存数据库或消息队列凭据。

## 当前限制与判断

当前已部署版本适合“一台 GPU 主机 + 平台服务可达”的拓扑；Control Service、网关和 GPU exporter 可以分机，只要浏览器能访问其地址且 CORS 允许。多 GPU 主机的 GPU 全量汇总目前需要后续增加地址列表或 GPU 聚合器，不能仅靠把不同主机的容器都使用同一个 `9400` 端口解决。

建议先采用方案 B 验证多机采集，再在主机数量增加或需要 Prometheus 历史趋势时采用方案 C。Control Service、Gateway、A 服务和七类算子的 HTTP/WebSocket 合同无需改变。
