# 算子项目统一结构整改 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将七个算法算子统一为规范项目名、`app` Python 包和 `app.main:app` 启动入口，同时保持接口与算法行为不变，并在最终验收后移除子项目 Git 元数据。

**Architecture:** 采用逐项目原地迁移，每个项目独立完成目录移动、导入修正、文档与 Docker 更新、静态检查、启动和真实推理，再进入下一个项目。根目录 `AGENTS.md` 定义公共约束，项目级 `AGENTS.md` 记录服务特有的入口、配置、接口和验证方式；`ai_quality` 删除并指向已抽离的视觉调度器仓库。

**Tech Stack:** Python 3.10、FastAPI、Uvicorn、Conda、Docker、pytest、WebSocket、FunASR、PaddleOCR、FastDeploy、OpenCV、YOLO。

**实施状态（2026-08-03）：** 全部任务已完成并通过最终验收。七个子项目的 `.git` 已从项目目录移出；为保留一次本机恢复机会，原元数据暂存于 `/tmp/algorithm-embedded-git-backup.0flYpU`。文本分析服务随后作为第八个算子由 `llm_api_refactor` 迁移为 `text_analysis`，其 Git 元数据由独立重命名计划处理；独立视觉编排仓库 `.git` 未改动。

## 文件结构与责任

- `AGENTS.md`：整个算法工作区的公共 Harness 规则和项目地图。
- `asr_online/AGENTS.md`、`asr_offline/AGENTS.md`、`facerec/AGENTS.md`、`ocr/AGENTS.md`、`screen_det/AGENTS.md`、`ppt_slice/AGENTS.md`、`vbas/AGENTS.md`：单个算子的职责、入口、端口、环境、配置、接口和验证命令。
- 七个项目各自的 `app/main.py`：唯一 FastAPI/Uvicorn 应用入口，导出 `app`。
- 七个项目各自的 `app/api/`：HTTP/WebSocket 路由。
- 七个项目各自的 `app/core/`：配置、日志、模型生命周期和运行时基础设施。
- 七个项目各自的 `app/services/`：算法或业务服务；项目确无该层时不创建空目录。
- 七个项目各自的 `README.md`：人工使用、安装、启动和部署说明。
- 七个项目各自的 `docker/` 或根级 `Dockerfile`：容器构建和统一入口。

本计划不提交任何子项目现有改动。七个子项目均有用户脏文件，现有 `.git` 只用于迁移差异核对；全部验证后按用户要求删除。
