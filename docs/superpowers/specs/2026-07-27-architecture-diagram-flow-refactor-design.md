# 算法调度架构图流程线重构设计

## 目标

重构 `algorithm-scheduling-architecture-review.html` 的架构图表达，解决当前单张画布同时展示控制、离线、在线、实时、注册和资源关系导致的连线密集、长线交叉和阅读顺序不明确问题。

重构后的页面用于方案评审，而不是运行时管理后台。页面首先帮助评审者快速理解平台边界，再按需查看四类详细流程。

## 已确认部署前提

- A 上游只负责提交任务和查询任务状态。
- A 为离线课程任务提供可下载的 T、S、P 三路视频 URL。
- 调度平台、全部算法服务、PostgreSQL、Kafka 和 Redis 部署在同一台服务器。
- PostgreSQL、Kafka 和 Redis 分别运行在独立 Docker 容器中。
- 离线服务通过统一 Docker 挂载访问宿主机 `/data/course`。
- 第一版不展示 Kubernetes。
- 第一版暂不展开失败任务的文件保留与恢复策略。

## 页面信息架构

页面保留现有评审结论、在线接口契约、状态模型和组件详情，在主架构区域采用两级表达：

1. 一张始终可见的简洁平台总览。
2. 离线任务、在线图片、实时语音、注册部署四张可切换详图。

原有“全部、控制面、离线、在线图片、实时语音”透明度筛选改为详图页签。切换时只显示当前详图，其他详图使用 `hidden` 或等效机制完全移出展示，不保留半透明节点和连线。

打印时依次展开平台总览和四张详图。

## 平台总览

总览只表达平台的主要边界和三条业务链路：

```text
A 上游
   ├─ 离线任务接入 ─→ 离线编排与执行 ─→ 业务结果库
   ├─ 在线图片网关 ─→ 同步算子路由 ───→ 同步响应
   └─ 实时 ASR 网关 → 会话实例路由 ───→ 实时字幕

支撑层：注册中心 · PostgreSQL · Kafka · Redis · /data/course
```

总览不展开 Outbox、媒体处理、算法适配器、TIAS 内部聚合和实例心跳。支撑层只使用一条横向基础设施带表达服务范围，不与每个业务节点逐一连线。

总览最多保留八条业务关系线。

## 离线任务详图

### 接入与媒体准备

```text
A 提交 T/S/P URL
→ 任务接入服务
→ 同一事务写入 course_job 与 outbox_event
→ Outbox 发布器
→ Kafka
→ 课程 DAG 编排器
→ 媒体准备 Worker
→ /data/course/{course_job_id}/source/T.mp4、S.mp4、P.mp4
```

任务接入 HTTP 请求不下载视频。媒体准备 Worker 在异步任务中下载三路视频，下载完成后才释放依赖本地媒体的节点。

### 课程工作目录

```text
/data/course/{course_job_id}/
├── source/
│   ├── T.mp4
│   ├── S.mp4
│   └── P.mp4
├── audio/
│   └── teacher.wav
├── frames/
│   ├── teacher/
│   └── student/
├── ppt/
│   └── slices/
├── temp/
└── manifest.json
```

所有离线 Docker 容器使用相同容器内路径挂载 `/data/course`。Kafka 只传递任务标识、路径和元数据，不传递视频、WAV、图片或 Base64 二进制。

### 三条平行处理泳道

离线详图在媒体准备之后拆成三条互不穿线的泳道：

```text
ASR：T 或配置的主音轨 → WAV → 离线 ASR → /v1/course_overviews

PPT：P → PPT 切片 → 每个 ppt_image_id 执行 OCR
    → 每张 OCR 文本调用 /v1/extract_keywords

视觉：T/S → 外部 `jy-vision-orchestrator-server` 视觉编排与聚合
```

三条泳道的结果通过一个汇总点进入业务结果落库。全部必需结果确认落库后，DAG 执行最终 `CLEANUP_WORKSPACE` 节点并删除课程工作目录。

PPT 切片和 TIAS 告警快照如果属于需要长期展示的业务资产，应先复制到长期业务资源目录，不随课程工作目录清理。

### 视觉编排复合节点

第一版复用已抽离的 `jy-vision-orchestrator-server` 复合处理能力，不立即拆成多个平台 DAG 节点。离线详图使用虚线边界展开其内部步骤：

```text
读取本地 T/S
→ 按 FrameIntervalSeconds 抽帧
→ 按 TiasBatchSize 分批
→ 选择 TIAS 实例
→ 学生与教师帧推理
→ 聚合视觉指标
→ 生成快照、时间线、行为统计和评分结果
→ 写入对应业务表
```

`jy-vision-orchestrator-server` 需要支持读取 `/data/course/{course_job_id}/source/T.mp4` 和 `S.mp4`，避免再次通过 HTTP 下载相同视频。其抽帧、VBas 批量调度、聚合和结果写入逻辑继续复用。

图中标记该组件为“第一版复合 Worker”，后续才考虑把媒体、推理、聚合和写入拆成统一平台节点。

## 在线同步图片详图

### 输入边界

- 上游直接在 HTTP 请求中携带 Base64 图片。
- 平台不接收 RTSP 或其他持续视频流。
- 平台不拉流、不截图、不使用 `/data/course`。
- 在线请求不进入 Kafka，不创建课程 DAG。
- 默认不保存 Base64 图片和算法结果。

### 三个北向接口

```text
POST /v1/online/tias/analyze
POST /v1/online/face/recognize
POST /v1/online/image-quality/detect
```

平台根据接口确定 `operator_code`，查询 Redis 注册状态并原子占用一个实例并发槽，然后把整个 HTTP 请求发送给选定实例：

```text
上游 Base64 请求
→ 同步推理网关
→ operator_code
→ 注册中心查询与 inflight 占位
→ 选择一个实例
→ 算子适配器
→ 算子实例
→ 统一响应
→ 释放 inflight
```

三个接口分别映射：

| 北向接口 | 内部算子接口 |
|---|---|
| `/v1/online/tias/analyze` | `/AE/SyncTasks2` |
| `/v1/online/face/recognize` | `/recognize` 或 `/recognize/batch` |
| `/v1/online/image-quality/detect` | `/detect_all` |

### 单图约定与多图兼容

- 接口文档要求上游尽量采用单图单请求。
- 代码层面不严格拒绝多图请求。
- 调度粒度始终是完整 HTTP 请求，而不是单张图片。
- 多图请求不会被网关拆到多个实例，也不执行跨实例结果聚合。
- 如果算子对多图请求返回部分成功，网关在统一响应外壳中保留该结果。
- 多个并发 HTTP 请求通过请求级容量路由分散到不同实例。
- 后续只有出现明确业务需求或压测证明存在瓶颈时，才重新评估跨实例分片。

### 错误语义

- `429`：存在实例，但全部实例当前满载。
- `503`：没有在线且可调度的实例。
- `504`：选定算子调用超时。
- `502`：算子发生平台级技术故障。
- 算子业务结果和多图部分成功信息保留在统一响应 `data` 中。

## 实时语音详图

```text
直播音频
→ WebSocket 网关
→ 查询实时 ASR 实例
→ 会话开始时绑定一个实例
→ 增量字幕
→ 播放器
```

实时语音不进入离线 Kafka，不为每句话创建 `NodeRun`，默认不写业务数据库。一次连接期间保持实例绑定，连接断开后允许重新选择实例。

## 注册与部署详图

```text
算法 Docker 实例
→ 注册 / 心跳 API
→ Redis TTL 注册表

离线执行器 / 同步网关 / 实时网关
→ 查询实例与容量
→ 占用并调用目标实例
```

同一台服务器中展示以下部署组：

- PostgreSQL Docker 容器，保存平台任务状态与 Outbox。
- Kafka Docker 容器，承载离线任务事件。
- Redis Docker 容器，保存实例 TTL、容量占位和 Worker 控制状态。
- 平台服务 Docker 容器。
- 算法服务 Docker 容器。
- 宿主机 `/data/course` 共享课程工作目录。

PostgreSQL、Kafka 和 Redis 使用 `/data/platform/...` 下各自独立的持久化目录，不放入 `/data/course`。

同一个算法容器端点注册为一个实例；容器内 FastAPI/Uvicorn worker 不分别注册。实例注册至少包含 `instance_id`、`operator_code`、`service_url`、`status`、`max_concurrency` 和 `last_heartbeat`。

## 视觉与连线规则

- 只使用水平和垂直正交折线，不使用跨区域长距离曲线。
- 所有主要业务流程从左向右阅读。
- 实线表示业务数据流。
- 虚线只表示注册、心跳、状态查询或复合节点内部边界。
- 返回过程不画反向箭头，以“结果落库”“同步响应”或“实时字幕”作为终点。
- 每张详图最多使用一个扇出点和一个汇聚点。
- 线路标签保持水平，不旋转文字。
- 标签靠近对应线段，不跨越节点。
- 用编号步骤帮助评审者按顺序阅读。
- 保留现有点阵背景和颜色语义，但不在页签之间共享连线。
- 组件详情面板继续展示职责、输入、输出和边界。

## 交互设计

- 默认显示平台总览和“离线任务”详图。
- 页签包括“离线任务、在线图片、实时语音、注册部署”。
- 切换页签时完整替换详图，不改变总览。
- 保留缩放、复位、打印和组件详情功能。
- 缩放只作用于当前详图，不作用于整页。
- 窄屏下总览和当前详图分别允许横向滚动。
- 打印模式展开全部详图并隐藏交互工具栏。

## HTML 实现范围

- 继续输出单文件 `algorithm-scheduling-architecture-review.html`。
- CSS 和 JavaScript 全部内嵌。
- 不依赖网络、外部字体、图标库或构建工具。
- 不修改任何现有算法项目代码。
- 本次只修改架构评审页面和对应的依赖-free 契约测试。
- 对 `ai_quality` 的本地路径支持只作为架构要求表达，不在本次 HTML 重构中实现。

## 验收标准

- 总览业务关系线不超过八条。
- 页面包含四个详图页签，任一时刻只显示一张详图。
- 每张详图中不存在跨越其他业务泳道的长距离曲线。
- 离线详图明确展示统一下载、共享目录、三条处理泳道、`ai_quality` 聚合和最终清理。
- 在线详图明确展示 Base64 输入、请求级实例选择和三个北向接口。
- 在线详图不出现 RTSP、拉流或截图节点。
- 在线详图明确说明多图请求不跨实例拆分。
- 实时语音和在线图片使用独立详图。
- 注册部署详图展示三个基础设施 Docker 容器和 `/data/course` 共享挂载。
- 页签、缩放、复位、组件详情和打印交互具有契约测试。
- 页面无外部资源依赖，内嵌脚本通过语法检查。
- 桌面和窄屏布局保持可读，不出现节点文字或控件重叠。

## 非目标

- 不实现真实调度服务、注册中心、数据库、Kafka 消费或文件清理逻辑。
- 不在本次修改中重构 `ai_quality`。
- 不实现请求内跨实例图片分片。
- 不增加批量北向接口。
- 不引入 Kubernetes。
- 不把架构评审页面改造成运行时运维后台。
