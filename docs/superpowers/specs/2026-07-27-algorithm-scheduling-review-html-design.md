# 算法调度平台架构评审 HTML 设计

## 目标

生成一个可直接在浏览器打开的单文件 HTML，用于评审当前算法调度平台架构，并展示建议的改进方案。页面既要保留原始架构图的点阵背景、分区色块和连线风格，也要明确区分控制面、离线执行面、在线同步图片执行面、实时语音执行面、注册发现、算子部署和结果落库。

该页面主要服务于内部技术讨论、方案评审、截图归档和浏览器打印，不作为平台运行时管理后台。

## 输出范围

- 输出一个独立 HTML 文件，CSS 和 JavaScript 全部内嵌。
- 不依赖服务端、构建工具、外部字体、外部图标库或网络资源。
- 支持桌面浏览、窄屏横向查看和浏览器打印。
- 不修改任何现有算法项目代码。

## 页面结构

### 1. 顶部信息区

展示页面标题、评审范围和图例。图例使用稳定颜色语义：

| 颜色 | 含义 |
|---|---|
| 天蓝色 | 北向接入、控制面和通用平台组件 |
| 品红色 | 算子适配器与算法能力 |
| 橙色 | GPU 节点和计算资源 |
| 绿色 | 平台数据库、结果写入和数据组件 |
| 紫色 | A 数据库或其他业务数据库 |
| 红色 | 风险、职责错误或必须修正的问题 |

### 2. 架构评审结论区

以紧凑列表展示当前图中的关键问题，并标识严重程度：

1. 缺少视频下载、WAV 提取和抽帧等媒体处理能力。
2. 未区分实时 ASR WebSocket 会话与 TIAS、人脸、图像质量的同步图片请求。
3. 每种算法一个独立调度器会产生重复的实例选择、状态更新和重试代码。
4. 各调度器直接写业务数据库会造成数据库协议和表结构耦合。
5. 图中缺少课程脑图和 OCR 关键词提取两个文本分析节点。
6. 课程任务接入缺少数据库落库与 Kafka 发布的一致性设计。
7. 一张 GPU 部署所有算子的画法容易误导实际资源部署。

### 3. 改进后的主架构图

主架构图使用点阵画布和分区布局，包含以下区域：

#### 北向接入

- A 上游服务通过任务接入服务提交课程信息和视频 URL。
- 任务接入服务在同一数据库事务中写入 `course_job` 与 `outbox_event`，提交成功后返回 `course_job_id`。
- Outbox 发布器将待发布事件发送到 Kafka，成功后把任务状态更新为 `QUEUED`。
- A 上游服务通过控制面 API 查询、补跑和取消任务。

#### 控制面

- 任务接入服务：校验课程请求、生成任务标识并完成任务初始落库。
- Outbox 发布器：解决数据库写入成功但 Kafka 发布失败的双写不一致问题。
- 控制面 API：提供任务查询、补跑、取消和运维查询。
- 课程编排器：根据 T、S、P 视频和节点依赖创建课程 DAG。
- 平台任务数据库：保存 CourseJob、NodeRun 和 Attempt。
- 运维视图：读取任务数据库与注册中心状态，不直接参与算子调用。

#### 注册发现

- 算子实例主动注册并定期心跳。
- Redis 保存带 TTL 的实例在线状态。
- 注册信息至少包含 instance_id、operator_code、service_url、status、max_concurrency 和 last_heartbeat。
- 执行器查询注册中心并选择实例，算子不向适配器注册。

#### 离线执行面

- 媒体处理执行器：下载视频、提取 WAV、按策略抽帧。
- 通用离线执行器：承载同步 HTTP 算子的调用、标准错误映射、重试和状态更新。
- 算子适配器：离线 ASR、OCR、离线算法能力和文本分析。
- PPT 提交适配器与回调接收器：支持异步回调调用模式。
- PPT 回调中的每张切片保留独立 `ppt_image_id`；编排器为每张图片创建 OCR 节点和依赖该 OCR 节点的关键词提取节点。
- `/v1/extract_keywords` 按单张 PPT 图片粒度调用，不合并全课 OCR 文本。
- 结果写入器：按 node_run_id 幂等写入对应业务数据库。

#### 在线同步图片执行面

- 上游系统继续负责从直播 RTSP 流截图，平台第一版不接收 RTSP，也不负责在线截图。
- 同步推理网关分别释放 TIAS、人脸对比和图像质量的北向业务接口。
- 同步推理网关根据 `operator_code` 查询注册中心，按实例状态与实际并发占用选择并占用实例。
- 算子适配器将平台请求转换为 TIAS `/AE/SyncTasks2`、人脸 `/recognize` 或 `/recognize/batch`、图像质量 `/detect_all` 的内部请求。
- 每个图片请求同步返回，不进入离线 Kafka，不创建课程 DAG 节点，也不在网关内长时间排队。
- 全部实例不可用或满载时返回 HTTP 429 或 503；调用超时返回 HTTP 504。
- 平台记录 request_id、operator_code、instance_id、耗时和结果码，不默认保存图片内容。

#### 实时语音执行面

- 实时 ASR 网关在会话开始时选择实例并维持 WebSocket 长连接。
- 实时 ASR 会话不进入普通课程节点重试队列。

#### 算子实例与资源

- GPU 节点按真实部署展示不同算子实例，不要求每张 GPU 部署全部能力。
- CPU 算子和 GPU 算子允许分别部署。
- 图中仅表达能力与资源归属，不把 Uvicorn worker 当成独立注册实例。

#### 结果存储

- 平台任务数据库只保存调度元数据、调用记录和业务结果引用。
- 离线 ASR、OCR、PPT 切片和文本分析结果通过结果写入器进入对应业务数据库。
- 同步图片请求的算法结果通过统一响应直接返回上游；是否写入业务数据库由上游业务服务决定。
- 实时字幕默认只返回播放器，不进入业务结果库。

## 关键业务流程

### 完整离线流程

```text
A 提交课程信息和视频 URL
-> 任务接入服务写入 course_job + outbox_event
-> Outbox 发布器
-> Kafka
-> 课程编排器创建 DAG
-> 媒体处理执行器准备 WAV、帧图片和 P 视频
-> 离线 ASR / PPT 切片 / 其他离线算法节点
-> ASR 文本调用 /v1/course_overviews
-> PPT 每张切片按 ppt_image_id 调用 OCR
-> 每张 OCR 文本分别调用 /v1/extract_keywords
-> 结果写入器幂等落库
-> 课程任务完成
```

### 实时语音流程

```text
直播音频流
-> 实时 ASR 网关
-> 注册中心选择实时 ASR 实例
-> WebSocket 会话
-> 字幕返回直播播放器
```

### 在线同步图片流程

```text
上游从直播 RTSP 流截图
-> 调用同步推理网关业务接口
-> 注册中心查询与并发占位
-> TIAS / 人脸 / 图像质量适配器
-> 选定的算子实例
-> 统一响应外壳返回上游
```

## 在线同步接口设计

平台北向接口使用业务路径，不暴露算子的历史内部路径：

| 平台北向接口 | 内部算子接口 |
|---|---|
| `POST /v1/online/tias/analyze` | `POST /AE/SyncTasks2` |
| `POST /v1/online/face/recognize` | `POST /recognize` 或 `POST /recognize/batch` |
| `POST /v1/online/image-quality/detect` | `POST /detect_all` |

同步接口使用统一响应外壳，`data` 保留算子的原始业务结果：

```json
{
  "request_id": "01J...",
  "code": 200,
  "message": "success",
  "data": {}
}
```

平台级错误码至少区分：参数错误 400、实例满载 429、无可用实例 503、算子调用超时 504 和算子技术故障 502。算子的业务结果放在 `data` 中，由对应适配器判断本次调用是否属于平台技术成功。

TIAS 当前仅在 `TiasExposeLegacySyncTasks=true` 时暴露 `/AE/SyncTasks2`，且该接口响应中的 `FreeCapacity` 当前为固定值，不能作为网关实例选择依据。实例选择必须以注册中心中的 `status`、`max_concurrency` 和平台维护的 `inflight` 为准。

## 交互设计

- 提供“全部、控制面、离线、在线图片、实时语音”分段视图。
- 切换视图时弱化无关区域并高亮相关组件和连线。
- 提供放大、缩小和复位按钮，按钮具有可访问名称和悬停提示。
- 提供打印按钮，调用浏览器打印并使用专门的打印样式。
- 点击关键组件时，在详情面板展示职责、输入、输出和不应承担的职责。
- 所有交互不改变架构内容，只改变查看方式。

## 视觉设计

- 使用浅灰点阵背景呼应原图，但减少空白和过长交叉连线。
- 页面采用白色和浅灰为主，不使用渐变、装饰光斑或大面积单色背景。
- 架构组件使用小圆角矩形，圆角不超过 8px。
- 控制面、执行面和资源层使用横向全宽分区，不使用卡片嵌套。
- 主架构画布设置稳定最小宽度；窄屏使用横向滚动，禁止挤压节点导致文字重叠。
- 字号使用固定响应断点，不按视口连续缩放。

## 状态模型展示

页面底部展示任务层级：

```text
CourseJob
└── NodeRun
    └── Attempt
```

并展示节点状态：

```text
PENDING -> READY -> DISPATCHED -> RUNNING
                              -> WAITING_CALLBACK
                              -> SUCCEEDED / FAILED / CANCELLED
```

课程任务在接入阶段依次经历 `RECEIVED`、`PUBLISH_PENDING` 和 `QUEUED`，执行阶段状态包含 RUNNING、PARTIAL_SUCCESS、SUCCEEDED、FAILED 和 CANCELLED。

## 第一版边界

- 不展示 Kubernetes，部署环境保持 Docker。
- 不实现真实任务调度、注册、数据库访问或监控接口。
- 不从现有服务动态读取实例状态，页面使用设计态示例数据。
- 平台第一版不接收 TIAS、人脸和图像质量业务的 RTSP 流，也不承担这些在线业务的截图工作。
- 不提供架构节点拖拽和在线编辑能力。
- 不把该页面包装成管理后台或营销页面。

## 验证要求

- 在桌面宽屏视口检查完整架构、箭头、节点和文字无重叠。
- 在窄屏视口检查顶部信息正常换行，架构画布可横向滚动。
- 验证全部视图筛选、缩放、复位、组件详情和打印按钮。
- 检查浏览器控制台无运行时错误。
- 检查页面不依赖外部网络资源。
